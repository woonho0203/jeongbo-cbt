## 1. 제안 이유

현행 헌법 v1.0은 마스터프레임워크 v2.3을 기반으로 제정됐다. 이후 v2.4는 웹·앱·대시보드가 있는 프로젝트의 헌법에 `검증된 인기 UI 참조 원칙`을 두도록 추가했다.

정보처리기사 CBT에는 풀이 화면·OMR·결과·통계 대시보드가 있으므로 적용 대상에는 해당한다. 다만 이 변화는 데이터 정확성이나 해설 품질보다 우선할 수 없고, 특정 디자인을 그대로 복제하는 허가도 아니다.

## 2. 현행 헌법과의 차이

| 항목 | 현행 v1.0 | 마스터프레임워크 v2.4 |
|---|---|---|
| 데이터·해설·앱 무결성 | 제3~6조에 명시 | 유지 |
| 인기 UI 참조 원칙 | 없음 | UI 프로젝트 헌법에 필수 |
| 사용자 승인 | 헌법 개정 시 필수 | 동일 |

## 3. 제안 조문

현행 제6조 뒤에 다음 조문을 신설한다.

```text
제6조의2 검증된 인기 UI 참조 원칙

1. 웹·앱·대시보드 등 사용자 인터페이스를 설계할 때는 Figma Community의
   Dashboards UI Kits 등에서 현재 인기와 활용도가 검증된 UI 키트·디자인 패턴을
   우선 참고하여 프로젝트에 맞게 적용한다.
2. 프로젝트 목적, 정보 구조, 원문 충실성, 교육적 정확성, 접근성을 해치는 유행은
   배제하고 특정 디자인을 맹목적으로 복제하지 않는다.
3. 인기 판단, 후보 비교, 적용 범위와 라이선스 확인의 세부 기준은 관련
   법률·시행령·시행규칙·고시에 위임한다.
4. 이 조는 제4조의 우선순위를 바꾸지 않는다. 데이터 무결성과 해설 교육 품질이
   UI 유행보다 항상 우선한다.
```

참조 링크: [Figma Community Dashboards UI Kits](https://www.figma.com/ko-kr/community/ui-kits/dashboards?resource_type=files&editor_type=figma)

## 4. 승인 시 필요한 후속 작업

1. 현행 헌법을 v1.1로 개정하고 개정 이력에 사용자 승인일·이유를 기록한다.
2. UI·UX 분야 법률을 신설하거나 기존 관련 법률에 인기 판단·프로젝트 적합성·접근성·라이선스 원칙을 배치한다.
3. 시행령·시행규칙·고시에 후보 비교 절차와 체크리스트를 둔다.
4. 라우터의 UI 작업 읽기 목록을 갱신한다.
5. 헌법재판소법에 따라 위헌·계층적합성·충돌심판을 수행한다.

## 5. 승인 전 금지

- 이 제안서를 승인된 헌법으로 인용하지 않는다.
- 특정 Figma 파일을 조사·선정·복제했다고 가정하지 않는다.
- 사용자 승인 없이 현행 헌법 파일을 수정하거나 버전을 올리지 않는다.
