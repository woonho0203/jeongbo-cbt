## 제1조 목적

이 법은 CBT 학습 데이터의 형식과 무결성을 정해, 어떤 작업(추출·해설·검수)을 하더라도 문제 원문과 앱 동작이 보존되게 한다.

## 제2조 정의

1. **데이터 파일**: 회차별 기출 `data/exam_*.json`, 유형별 연습 `data/category_*.json`.
2. **문항 객체**: `questions[]` 배열의 한 원소.
3. **불변 필드**: `examId`, `title`, `qnum`, `subject`, `subjectName`, `stem`, `options`, `answer`.
4. **작업 대상 필드**: `explanation`, `image`, `table` (해설·자료 보강 대상).
5. **자료 필드**: `image`(그림 경로), `table`(HTML 표).
6. **정답 필드(`answer`)**: 단일 정답은 정수, 공식 정답이 전항정답·복수정답인 문항은 인정 보기 번호의 배열로 저장한다. 앱은 배열을 복수정답으로 채점한다(`public/js/util.js`의 `isCorrectAnswer`). 예: `[3,4]`(복수정답), `[1,2,3,4]`(전항정답).

## 제3조 기본 원칙

1. 불변 필드는 PDF 원본 대조 없이 수정하지 않는다. (헌법 제5조 1호)
2. 작업은 원칙적으로 `explanation`, `image`, `table`만 추가·교체한다.
3. 모든 수정 후 JSON은 정상 파싱되어야 하고, 앱이 해당 회차·유형을 정상 로딩해야 한다. (헌법 제3조 3호)
4. 한 번에 대량 수정한 뒤에는 반드시 JSON 파싱 점검과 앱 실행 확인을 한다.
5. `answer`는 정수 또는 배열(제2조 6호)이며, 그 값(배열이면 모든 원소)은 1 이상 `options` 개수 이하여야 한다. 전항정답·복수정답은 출제기관 공식 정답 발표에 근거할 때만 배열로 둔다.

## 제4조 허용

1. `explanation` 신규 작성·보강·재작성.
2. `image` 또는 `table` 필드 신규 추가.
3. 원문 의미를 바꾸지 않는 범위의 띄어쓰기·조사 교정 (검수법에 위임).
4. 앱 렌더링을 위한 JSON 문자열 이스케이프 정리.

## 제5조 금지

1. 불변 필드(제2조 3호) 임의 변경.
2. 다른 문항·다른 회차의 자료·해설을 현재 문항에 혼입.
3. 코드·SQL·수식·파일명·영문 식별자 내부 표기 임의 변경.
4. JSON 구조(따옴표·이스케이프·중괄호) 파손.
5. 기존에 정상 삽입된 `image`·`table`을 검수 없이 덮어쓰기.

## 제6조 품질 기준

- JSON 필수 필드 점검(04_시행규칙)을 통과해야 한다.
- 불변 필드 변경이 필요하다고 판단되면 임의 수정하지 않고 유권해석 절차로 사용자에게 확인한다.
- 세부 점검 명령·통과선은 04_시행규칙과 05_고시에 위임한다.

## 제7조 다른 법률과의 관계

1. 추출·삽입법, 해설작성법, 검수법은 모두 이 법의 불변 필드·무결성 규정을 전제로 한다.
2. 이 법과 다른 법률이 충돌하면 데이터 무결성(헌법 제4조 1순위)을 우선한다.
