# 검수보고_2026-07-26_2016-2_100문항_자료정답원본정합성검수

## 1. 검수 목적

2단계 원본 데이터 정합성 확보의 다음 실행 단위로 `data/exam_2016-2.json`을 보유 PDF와 대조했다.

이번 검수의 확정 범위는 다음과 같다.

- 문항 수와 `qnum` 연속성
- PDF 공식 정답표와 JSON `answer` 일치 여부
- `image`·`table` 자료 문항의 원본 위치·내용·혼입 여부
- PDF 표가 JSON에서 줄글로만 평탄화된 후보 여부
- 전체 JSON·이미지 경로·HTML 표·앱 API 무결성

`pdftotext`는 이 PDF에서 보기 상당수를 누락했고, Tesseract OCR도 로컬 PNG 입력을 읽지 못해 빈 결과를 냈다. 따라서 OCR 결과는 원문·보기 문자 단위 전수 판정 근거로 사용하지 않았다. 이번 보고서는 2016-2의 정답·자료·앱 무결성 검수 완료를 뜻하며, 모든 `stem`·`options`의 글자 단위 전수 교정 완료를 뜻하지 않는다.

## 2. 직접 원본과 검수 방법

- 직접 원본: `정보처리기사 문제/2016년2회_정보처리기사_필기_기출문제.pdf`
- 데이터: `data/exam_2016-2.json`
- 자료: `public/images/2016-2_q2.png`, `public/images/2016-2_q4.png`, `public/images/2016-2_q32.png`, `public/images/2016-2_q35.png`, `public/images/2016-2_q72.png`
- 표: `data/exam_2016-2.json` Q27 `table`

PDF는 A형이고 JSON `qnum`과 PDF 인쇄번호가 1~100으로 일치한다. PDF 1~8쪽을 220DPI PNG로 렌더했고, 최종 판단은 렌더 이미지와 PDF 정답표를 직접 확인해 내렸다.

보조 도구 실행 결과:

- `pdftotext -layout`: 문제 본문 일부 확인에는 유용했으나 보기 누락이 많아 options 전수 판정에는 부적합
- Tesseract OCR: `/tmp/.../*.png` 입력을 읽지 못해 0바이트 결과 생성, 판정 근거에서 제외
- `scripts/audit_plaintext_table_candidates.js --fail-on-candidates`: 미확인 표 평탄화 후보 0건

## 5. PDF 표-텍스트 평탄화 후보

사용자 질문인 “표인데 표로 없고 글로만 들어간 문제도 잡아내나?”에 따라 표 평탄화 후보 점검을 포함했다.

자동 점검:

```text
node scripts/audit_plaintext_table_candidates.js --fail-on-candidates
→ PDF 표-텍스트 평탄화 후보 없음
```

렌더 육안 확인:

- Q12·Q18·Q20: SQL/수식/문장 블록으로 행·열 표가 아님
- Q39·Q50·Q51·Q54·Q58·Q80·Q98: 박스형 지문 또는 순서/문장 나열이며, 행·열 구조가 정답 판단에 필요한 표가 아님
- Q27: 실제 행·열 진리표이므로 `table` 필드로 보존됨

판정: 2016-2에서 PDF 표가 JSON에 줄글로만 남은 미확인 후보는 발견하지 못했다.
