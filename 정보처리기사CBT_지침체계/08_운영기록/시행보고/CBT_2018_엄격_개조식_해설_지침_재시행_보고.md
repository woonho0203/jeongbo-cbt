## 4. 대표 보정 예시

### 2018년 1회 Q1

```text
- 개념 정의: 트리는 사이클이 없는 계층형 비선형 자료구조이며 노드와 간선으로 부모·자식 관계를 표현함
- 정답 분석: 'tree'는 문제 문장의 핵심 단서가 설명하는 실제 개념과 일치함. 따라서 용어의 정의와 문제 조건이 직접 연결되어 정답으로 판단함.
- 오답 분석:
  - 2번 network: 네트워크는 노드들이 연결된 구조를 뜻하지만, 사이클이 없고 계층 관계를 갖는 자료구조를 직접 가리키는 용어는 트리임 정답 보기와 달리 문제 문장의 핵심 정의나 계산 조건을 직접 만족하지 않으므로 제외함.
  - 3번 stack: 스택은 마지막에 삽입한 데이터가 먼저 삭제되는 LIFO 구조임 정답 보기와 달리 문제 문장의 핵심 정의나 계산 조건을 직접 만족하지 않으므로 제외함.
  - 4번 distributed: 분산 구조는 여러 컴퓨터나 노드가 작업과 데이터를 나누어 처리하는 구조임 정답 보기와 달리 문제 문장의 핵심 정의나 계산 조건을 직접 만족하지 않으므로 제외함.
- 주의(함정): 유사 문제에서는 보기 이름만 외우지 말고, 문제 문장의 동작·구조·제약 조건이 어떤 정의와 맞는지 비교해야 함.
```

### 2018년 2회 Q70

```text
- 정답 분석: '데이터 흐름 검사'는 프로그램 내부 변수의 정의(definition)와 사용(use) 경로를 추적하는 화이트박스 검사 기법임. 문제의 다른 보기들은 입력값과 출력 결과를 기준으로 검사하는 블랙박스 기법이므로, 내부 코드 흐름을 보는 데이터 흐름 검사는 종류가 다름.
- 개념 정의: 데이터 흐름 검사는 변수 값이 어디서 정의되고 어디서 사용되는지 분석해 정의되지 않은 변수 사용, 사용되지 않는 정의, 잘못된 값 전달 같은 결함을 찾는 화이트박스 테스트임.
- 오답 분석:
  - 1번 동치 분할 검사: 입력 영역을 같은 결과를 기대하는 동치 클래스별로 나누고 대표값을 검사하는 블랙박스 기법임.
  - 2번 원인 효과 그래프 검사: 입력 조건(원인)과 출력 결과(효과)의 논리 관계를 그래프로 모델링해 테스트 케이스를 만드는 블랙박스 기법임.
  - 3번 비교 검사: 같은 요구사항을 구현한 여러 프로그램이나 버전의 출력 결과를 비교해 오류를 찾는 블랙박스 계열 기법임.
- 주의(함정): 검사 기법 문제에서는 입력·출력만 보는 블랙박스인지, 내부 제어·자료 흐름을 보는 화이트박스인지 먼저 구분해야 함.
```
