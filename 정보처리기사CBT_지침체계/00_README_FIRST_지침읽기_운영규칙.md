# 00_README_FIRST — 지침 읽기·운영 규칙 (라우터)

이 문서는 정보처리기사CBT 지침체계의 입구다. **모든 작업은 이 문서를 먼저 읽고 시작한다.**

## 0. 최상위 원칙

1. 지침은 헌법 → 법률 → 시행령 → 시행규칙 → 고시 → 판례 → 유권해석 → 운영기록 순으로 우선한다. 충돌하면 항상 상위 문서를 따른다.
2. 전체 지침을 다 읽었다고 가정하지 않는다. **읽지 않은 문서는 존재하지 않는 것처럼 취급한다.** "전체 지침상으로는…" 같은 표현을 쓰지 않고, 실제로 읽은 문서만 근거로 판단하며 어떤 문서를 읽었는지 밝힌다.
3. 읽기 기본 순서: **00_README → 01_헌법 → 작업 관련 하위 문서.**

## 1. 첫 줄 의무 출력 (모든 응답)

모든 지침 기반 응답의 **첫 줄**에 아래를 출력한다. 실제로 읽은 문서만 적는다.

```text
[분류: 작업유형 | 읽음: 문서1, 문서2 | 심판: 필요/불요]
```

- 읽은 문서가 없으면 `읽음: 없음`.
- 첫 줄 보고가 빠지면 사용자는 `첫 줄 보고`라고만 입력하고, 모델은 즉시 분류부터 다시 한다.

## 2. 읽기 범위 원칙

```text
항상 읽기: 00_README + 01_헌법
작업별 읽기: 관련 법률 + 관련 시행령
필요 시 읽기: 관련 시행규칙 + 고시 + 판례 + 유권해석
기록 시 읽기: 08_운영기록 + changelog
검수·심판 시: 09_헌법재판소/헌법재판소법
```

## 6. 애매한 상황 처리

기존 지침으로 판단이 안 되면 임의로 확정하지 않는다.

```text
기존 유권해석(07) 확인 → 없으면 사용자에게 질문 (A안/B안/추천안, 1~3개)
→ 답변을 07_유권해석 문서로 저장 → 관련 지침·changelog 업데이트
```

## 7. 기존 법 수정 트리거

사용자가 "기존 법에 넣어줘 / 지침에 반영해줘 / [분야]법에 추가해줘 / 구조에 맞게 고쳐줘"라고 하면 지침 수정 작업으로 분류하고:

```text
1. 수정 대상 원본을 먼저 읽는다.
2. 새 규칙의 계층 성격을 분류한다.
3. 한 문서에 통째로 붙이지 않고 계층별로 분해해 반영한다.
   절대 원칙→헌법 / 분야 규칙→법률 / 작업 순서→시행령
   점수표·체크리스트→시행규칙 / 프롬프트·경로·템플릿→고시
   사례→판례 / 애매한 판단→유권해석 / 이력→changelog
4. 연동 수정 문서까지 함께 수정한다.
5. 수정 직후 헌법재판소 자동 심판(위헌·계층적합성·충돌)을 받는다.
6. changelog 기록 후 결과 보고 (수정 파일·계층별 반영·충돌 검토·남은 애매점).
```

## 8. 헌법재판소 심판 트리거

자동 심판(요청 없어도 필수): 새 지침 생성 직후 / 기존 지침 수정 직후 / 같은 쟁점 유권해석 3회 누적 / 체계 최초 생성 직후 / 재발방지 기준 포함 판례·결정례 생성 직후 / 이행 '대기' 잔존 상태로 다음 작업 시작 시.

청구 심판: "검수해줘 / 심사해줘 / 헌재 돌려줘 / 위헌인지 봐줘 / 계층 맞는지 봐줘 / 전체 지침 검수해줘 / 이거 승격시켜도 돼?".

심판 작업 읽기 목록:
```text
- 00_README_FIRST_지침읽기_운영규칙.md
- 01_헌법/헌법_정보처리기사CBT_정체성헌법_v1.0.md
- 09_헌법재판소/헌법재판소법_v1.2.md
- 심판 대상 문서
```
심판 결과는 결정문(합헌/헌법불합치/위헌)으로 09_헌법재판소/결정례/에 저장하고 changelog에 기록한다. 위헌 결정 지침은 수정 전까지 작업 근거로 쓰지 않는다.

## 10. 금지사항

1. 라우터를 읽지 않고 작업 시작 금지.
2. 읽지 않은 문서를 근거로 판단 금지.
3. 애매한 상황 임의 확정 금지.
4. 사용자 답변을 유권해석으로 남기지 않고 지나가기 금지.
5. 점수표를 법률에·프롬프트를 법률에·절차 변경을 시행령 외 문서에 넣기 금지.
6. 문제 원문(stem)·보기(options)·정답(answer)을 PDF 대조 없이 변경 금지. (헌법 제5조)
7. changelog 기록 없이 수정 완료 처리 금지.
8. 하위 지침으로 상위 지침 무시 금지.
