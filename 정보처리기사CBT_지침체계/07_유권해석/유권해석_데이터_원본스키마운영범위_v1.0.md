## 1. 애매한 상황

저장소 전수 분석에서 다음 기준이 명확하지 않거나 서로 충돌했다.

1. `category_*.json`이 회차 문제에서 파생한 복제본인지, 유형별 PDF를 독립 원본으로 삼는지.
2. `image`와 `table`을 동시에 가진 4문항을 허용할지.
3. 회차 문제의 `subjectName`을 JSON에 저장할지, 앱의 추론만으로 충분한지.
4. 스키마 고시의 `answer` 형식을 정수로만 둘지, 공식 복수·전항정답 배열까지 허용할지.
5. 오래된 인덱스와 루트 README 정비를 데이터 무결성 작업에 포함할지.
6. 승인된 헌법 v1.0을 최신 마스터프레임워크와 즉시 맞출지, 별도 개정안으로만 제안할지.

## 2. 기존 지침 검토

- 헌법 제1조·제3조는 회차별·유형별 문제 모두 PDF 원본 보존과 앱 무결성을 요구한다.
- 데이터관리법은 `answer` 정수·배열을 이미 허용했지만, 스키마 고시는 정수만 적어 상하위 규정이 충돌했다.
- PDF 매핑 고시는 유형별 JSON마다 별도 PDF를 지정했지만, 자동점검 고시 제1조의4와 판례_010·결정례_2026헌가12는 유형별 데이터를 회차 데이터의 파생 사본으로 단정했다.
- 스키마 고시는 `image`와 `table` 중 하나만 쓰는 원칙만 두고 예외를 정하지 않았다.
- 앱은 `subjectName` 누락 시 대체 표시를 제공하지만, 회차 JSON 10문항에 실제 필드 누락이 있었다.
- 헌법 v1.0은 마스터프레임워크 v2.3을 기반으로 하며, v2.4에서 추가된 검증된 인기 UI 참조 원칙을 포함하지 않는다.

## 3. 사용자 질의

```text
category_*.json은 회차 문제에서 파생한 복제본입니까, 아니면 유형별 PDF를 독립 원본으로 삼아야 합니까?
이미지와 HTML 표를 동시에 가진 4문제는 원본 재현을 위한 공식 예외로 허용합니까?
모든 회차 문제에 subjectName을 저장해야 합니까, 아니면 앱의 문제 번호 기반 추론을 공식 허용합니까?
상위 법률에 맞춰 JSON 스키마 고시의 정답 타입을 정수 또는 배열로 정비해도 됩니까?
오래된 인덱스와 README 정비를 다음 데이터 무결성 작업 범위에 포함합니까?
프로젝트 헌법은 승인된 v1.0 그대로 유지하되, 이후 최신 상위 프레임워크와의 차이를 별도 개정안으로 제안할지 확인이 필요합니다.
```

## 4. 사용자 답변

```text
category_*.json: 독립
이미지와 HTML 표를 동시에 가진 4문제: ㅇ
나머지 네 항목: 추천대로 진행
```

`추천대로 진행`은 직전 설명에서 제안한 다음 네 기준을 승인한 것으로 해석한다.

1. 모든 회차 문항에 `subjectName`을 저장하고 앱 추론은 장애 방지용으로만 둔다.
2. 스키마 고시의 `answer`를 정수 또는 정수 배열로 정비한다.
3. 오래된 인덱스와 루트 README 정비를 데이터 무결성 범위에 포함한다.
4. 헌법 v1.0은 수정하지 않고 최신 마스터프레임워크와의 차이를 별도 개정안으로만 제안한다.

## 5. 최종 해석

1. `data/category_*.json`의 직접 원본은 각 유형별 PDF다. 회차 JSON과 유사하거나 같은 문항이 있어도 회차 JSON을 원본으로 보거나 자동 동기화하지 않는다.
2. 2026-07-26 현재 `category_code` Q46, `exam_2019-1` Q26, `exam_2020-3` Q44, `exam_2020-4` Q51은 `image`와 `table` 동시 사용의 공식 예외다. 원본 재현 필요성과 앱 무중복 렌더링은 계속 검수한다.
3. 모든 회차 문항은 `subject`와 대응하는 `subjectName`을 함께 저장한다. 앱의 추론·대체 표시가 있어도 저장 필드 누락을 정상으로 판단하지 않는다.
4. `answer`는 단일 정답 정수 또는 공식 복수·전항정답의 비어 있지 않은 정수 배열이다.
5. `exams_index.json`·`categories_index.json`과 루트 README는 실제 데이터가 바뀔 때 함께 정비하는 데이터 무결성 범위다.
6. 승인된 헌법 v1.0은 그대로 유지한다. 최신 마스터프레임워크와의 차이는 효력 없는 별도 개정 제안서로 작성하며, 사용자 승인 전에는 헌법에 반영하지 않는다.

## 6. 적용 조건

- 원문·보기·정답·자료를 추출·수정·검수할 때 적용한다.
- 스키마·인덱스·README·지침 버전을 정비할 때 적용한다.
- 회차와 유형별 파일 사이에 유사 문항이 발견됐을 때 적용한다.

## 7. 적용하지 않는 경우

- 사용자 승인 없이 새 복합 자료 예외를 추가하는 근거로 쓰지 않는다.
- 유형별 PDF 대조 없이 기존 category 데이터를 정답이라고 확정하는 근거로 쓰지 않는다.
- 헌법 개정 제안서를 승인된 헌법으로 취급하지 않는다.

## 9. 이후 적용 기준

유형별 데이터는 반드시 자기 유형별 PDF로 검수하며, 회차 데이터와의 유사성은 검색 단서로만 사용한다. 스키마와 인덱스는 앱의 보정 동작에 기대지 않고 저장 데이터 자체로 완결되게 유지한다.
