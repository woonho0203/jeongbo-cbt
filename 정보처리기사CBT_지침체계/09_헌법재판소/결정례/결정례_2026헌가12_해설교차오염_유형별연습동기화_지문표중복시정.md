## 1. 심판 대상 조항

이미지·표 검수 요청에서 시작해, (1) 해설 내 다른 과목 문항의 개념 정의 재사용, (2) 유형별 연습 사본이 원본과 동기화되지 않은 결손, (3) 지문에 표 데이터가 중복 표시되는 문제, 세 가지 서로 다른 실패 유형을 발견·시정하고 각각 판례로 등록한 뒤 재발 방지용 자동 점검 조항을 고시에 추가한 조치 전체.

## 2. 쟁점

1. 해설 41문항 재작성이 헌법 제5조 2호("다른 문제·다른 회차의 해설·이미지·표를 섞지 않는다")를 다시 어기지 않고 실제 문항 근거로 되어 있는가.
2. 유형별 연습 3문항(category_code Q46·Q48, category_calc Q13)을 stem·options·answer·explanation 전체 교체한 것이 헌법 제5조 1호(원본 대조 없는 임의 변경 금지)에 저촉되는가.
3. 지문-표 중복 정리 39건 중 일부(stem 일부 삭제)가 데이터관리법의 불변 필드 보존 원칙과 충돌하는가 — `stem`은 불변 필드이지만 표와 중복되는 원자료 텍스트 제거가 "내용 변경"인지 "표시 중복 제거"인지 판단이 필요하다.
4. 신설한 제1조의4(퍼지 매칭)가 8건의 거짓 양성을 냈는데, 이것이 조항 자체의 결함인지 명시적 한계인지.

## 3. 판단

- **위헌 여부: 없음.**
  - 41문항 재작성은 실제 stem·options·answer를 근거로 정답 개념과 오답별 근거를 새로 작성했고, 재작성 후 제2조의4(과목 교차 재사용 탐지)를 전체 데이터에 재실행해 잔여 교차 오염이 실제로 그 주제인 문항끼리의 정상 재사용(응집도/결합도) 1건만 남음을 확인했다. 헌법 제5조 2호가 금지하는 "다른 문제 것을 섞는" 상태가 해소됐다.
  - category_code Q46·Q48·category_calc Q13의 전체 교체는, 교체 이전 값 자체가 "PDF 원본과 대조된 정상 데이터"가 아니라 원본(exam_*.json)의 옛 버전이거나 옵션이 파편화된 오염 상태였다. 당시 회차 데이터를 근거로 전체 교체했고, 그 외 14건은 table/image만 복사했다. 2026-07-26 각 유형별 독립 원본 PDF와 다시 대조해 정합성을 재확정했다.
  - 지문-표 중복 정리는 `stem`의 **정보 내용**을 바꾸는 것이 아니라, `table` 필드가 이미 담고 있는 것과 완전히 동일한 원자료 텍스트를 제거해 중복 렌더링만 없앤 것이다. `(단, ...)` 단서·SQL 구문처럼 표에 없는 내용은 전부 보존했고, 표가 두 부분(전/후 비교)으로 나뉘는 2건은 삭제 대신 표 필드 자체를 확장해 정보 손실을 원천 차단했다. 데이터관리법의 불변 필드 보존 원칙은 "내용의 정확성"을 지키기 위한 것이지 "같은 정보의 중복 표시"를 보호하지 않는다.
- **계층 적합성: 오배치 없음.**
  - 세 가지 발견 모두 검수 절차의 새로운 사각지대이므로 05_고시_훈령_예규/고시_검수_자동점검명령에 배치하는 것이 맞다. 개별 데이터 수정(41+17+39=97건)은 시행규칙·고시가 아니라 데이터 자체에 반영했다.
- **충돌 여부: 없음.**
  - 제1조의4(신설)는 fs만 쓰는 순수 Node 스니펫으로 다른 조항과 실행 방식이 같다(제1조의3과 달리 Python·PDF 의존이 없어 하급 모델이 그대로 실행 가능).
  - 제1조의4가 짧은 공통 도입부(예: "다음 C언어 프로그램이 실행되었을 때…")를 가진 서로 무관한 문항 8건을 오탐한 것을 확인, 조항 자체를 폐기하지 않고 **"알려진 오탐 원인"**으로 조문에 명시해 제1조의3과 동일한 패턴(오탐 목록을 조문에 고정)을 따랐다. 이는 결함이 아니라 "앞 40자만 비교"라는 설계상 트레이드오프(넓게 잡되 육안 재확인 요구)이므로 충돌이 아니다.
- **이행확인심판**: 실제로 재실행해 확인했다.
  - 제2조의4를 전체 3,568문항+유형별 연습에 재실행 → 과목 3개 이상 교차 재사용 1건(정상: 응집도/결합도 문항끼리)만 남음을 확인.
  - 제4조의3을 전체 데이터에 재실행 → 지문-표 중복 0건 확인.
  - 제1조의4를 전체 데이터에 재실행 → 최초 12건 중 9건(정형화된 도입부 오탐, 육안 확인 완료) 남고 실제 결손 0건 확인. category_calc Q13(카티션 프로덕트)은 1차 스캔에서 놓쳤다가 2차(제1조의4 재실행)에서 잡혀 함께 시정했다.
  - 로컬 서버로 category_calc(카디널리티/차수, Division 연산), category_keyword(정규화 전/후) 문항의 실제 화면 렌더링을 확인했고, API 응답으로 정규화 전/후 2표 구조를 재확인했다.
  - 전체 34개 데이터 파일 JSON 파싱 유효성을 매 단계마다 재확인했다(오류 0건).
- **심판 점수**: 합헌성 30 / 계층적합성 30 / 무충돌성 18(제1조의4 오탐 8건을 조문 명시로 처리한 점 반영, 완전 무결은 아니므로 소폭 감점) / 형식적합성 10 / 참조무결성 10 — **총 98점**

## 6. 재발 방지 기준

1. 해설에 "개념 정의" 문구를 쓸 때는 그 정의가 **실제로 이 문항의 주제**를 설명하는지 확인한다 — 같은 문구가 과목 3개 이상에서 반복되면 재사용 오염을 의심한다.
2. `category_*.json`은 `exam_*.json`의 파생 사본이므로, 원본을 대량 수정한 직후에는 반드시 제1조의4를 실행해 사본이 뒤처지지 않았는지 확인한다.
3. `table`/`image` 필드를 추가하거나 복사할 때는 `stem`에 같은 데이터가 원자료 텍스트로 남아있는지 항상 함께 확인한다.
4. 퍼지 매칭 기반 점검(제1조의2·1의3·1의4)은 정형화된 공통 문구 때문에 거짓 양성을 낼 수 있으므로, 매칭 결과는 반드시 stem 전체(또는 options·answer)를 대조해 확정한 뒤 데이터를 수정한다.
