## 1. 심판 대상 조항

사용자는 다음 기준을 확정했다.

1. `category_*.json`은 각 유형별 PDF를 독립 원본으로 삼는다.
2. 현재 이미지와 HTML 표를 함께 가진 4문항은 원본 재현을 위한 공식 예외로 허용한다.
3. 모든 회차 문제에 `subjectName`을 저장하고 앱 추론은 장애 방지용으로만 둔다.
4. `answer` 스키마는 단일 정답 정수 또는 공식 복수·전항정답의 정수 배열로 둔다.
5. 오래된 인덱스와 README를 데이터 무결성 정비 범위에 포함한다.
6. 현행 헌법 v1.0은 그대로 유지하고 최신 마스터프레임워크와의 차이는 별도 개정안으로만 제안한다.

## 2. 쟁점

1. 유형별 PDF의 독립 원본 지위가 헌법의 PDF 원본 보존 원칙에 부합하는가.
2. 복합 자료 4건의 예외가 앱 무결성과 자료 혼입 금지를 해치지 않는가.
3. `subjectName` 명시 저장과 정수·배열 `answer`가 실제 앱 구조와 충돌하지 않는가.
4. 과거 판례_010·결정례_2026헌가12의 "파생 사본" 전제와 새 유권해석 사이의 충돌을 적절히 해소했는가.
5. 헌법 개정 제안서가 사용자 승인 없이 현행 헌법의 효력을 바꾸는가.

## 3. 판단

### 3.1 위헌 여부

- 유형별 문제도 "PDF 원본 그대로 보존"하라는 헌법 제1조·제3조의 적용 대상이다. 각 유형별 PDF를 직접 원본으로 고정하는 것은 원본 충실성을 강화하므로 위헌 사유가 없다.
- 복합 자료는 한 방식만으로 원본 정보를 온전히 재현할 수 없는 경우에 한정하고, 승인 목록·원본 대조·중복 표시·앱 렌더링 검사를 요구했다. 자료 혼입이나 렌더링 파손을 허용하지 않으므로 헌법 제3조·제5조와 양립한다.
- 회차 `subjectName` 명시 저장과 인덱스 count 일치 의무는 앱의 보정 동작에 기대지 않고 JSON을 스스로 완결시키므로 헌법 제4조 1순위 데이터 무결성을 강화한다.
- `answer` 정수·배열 규칙은 이미 상위 데이터관리법과 공식 복수·전항정답 8건에 맞는 기준이며 정답 임의 변경을 허용하지 않는다.
- 현행 헌법 파일은 수정되지 않았다. 개정 제안서는 효력 없음과 사용자 승인 전 금지를 명시했으므로 헌법재판소법 제2조 2항을 위반하지 않는다.

### 3.3 충돌 여부

- 데이터관리법의 배열 `answer` 허용과 스키마 고시의 정수 전용 규정이 v1.1에서 정수 또는 정수 배열로 일치했다.
- 자동점검 고시의 회차→유형 동기화 로직을 제거하고, 유형별 자기 PDF 대조 절차로 교체했다.
- 판례_010과 결정례_2026헌가12에는 후속 효력 안내를 추가했다. 당시 작업 이력은 보존하되 장래 적용 기준은 이번 유권해석과 결정으로 바뀐다.
- 앱의 `subjectName` 대체 표시는 장애 방지 수단으로 남아 있어 명시 저장 의무와 충돌하지 않는다.
- 승인된 복합 자료 목록은 실제 데이터의 4건과 정확히 일치한다.

### 3.4 자동 검증

- JSON·스키마·인덱스: 34개 파일, 3,568문항, 오류 0건.
- 회차 `subjectName`: 누락·불일치 0건.
- `answer`: 배열 8건을 포함해 형식·범위·중복 오류 0건.
- 인덱스: 29개 회차와 5개 유형의 식별자·제목·count 불일치 0건.
- 복합 자료: 승인된 4건만 존재하고 모두 `image`·`table` 필드 보유.
- 앱 API: 회차 29개·유형 5개 로딩, 회차 count 전부 100, 일반 모드 정답·해설 비노출, 4개 복합 자료 필드 전달 정상.
- 정적 파일·이미지 HTTP 응답 정상.
- 보기 셔플 해설 재매핑: 3,280문항 × 24순열, 오류 0건.
- JavaScript 문법 검사와 `git diff --check` 통과.
- 판례_010 대상 수량을 Git 이력으로 재계산해 `b2b3f9a` 13문항 + `289066a` 4문항 = 실제 17문항으로 확정했다. 기존 19문항 표기는 산술·기록 오류였다.
- 17문항을 각 유형별 PDF와 직접 재대조해 공식 정답 17/17 일치, 원본 표기·해설 불일치 3문항과 회차 번호 노출 이미지 5문항을 시정했다.
- 시정 후 전체 34개 파일·3,568문항 JSON·필수 필드·정답 타입·이미지 경로·표 형식·복합 자료 승인 목록 검사는 오류 0건이었다.
- 로컬 API에서 유형별 데이터 로딩, 일반 모드 정답·해설 비노출, Q46 복합 자료 전달, 새 이미지 5개의 HTTP 200 응답을 확인했다.
- 브라우저 시각 검수는 실행 환경에 연결 가능한 브라우저가 없어 수행하지 못했다. 복합 자료 4건과 새 이미지 5건의 실제 앱 화면을 최종 확정하는 근거로 API 검사만 사용하지 않는다.

## 4. 주문

사용자 유권해석과 이에 따른 지침·스키마·메타데이터 정비는 **합헌**이다.

다만 수정된 표·이미지의 실제 앱 화면 검사가 끝날 때까지 이 사건의 최종 종결은 유보한다.
