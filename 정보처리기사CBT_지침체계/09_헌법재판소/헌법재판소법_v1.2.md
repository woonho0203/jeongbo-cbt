# 제1장 총칙

## 제1조 목적

이 법은 지침 체계의 헌법 질서를 수호하기 위해, 모든 지침에 대한 위헌 여부와 계층 배치의 적합성을 심판하는 기준과 절차를 정한다.

## 제2조 지위

1. 헌법재판소는 지침 체계 안의 심판 기구다. 실제 수행자는 AI이며, 이 법의 절차에 따라 심판 역할을 수행한다.
2. 헌법재판소는 헌법을 개정할 수 없다. 헌법 개정이 필요하다고 판단되면 사용자에게 개정을 제안할 수만 있다.
3. 헌법재판소의 결정은 헌법보다 우선하지 않으며, 헌법을 기준으로만 판단한다.

## 제2조의2 심판 주체 (모델 등급)

1. 심판은 사용 가능한 모델 중 상급(고성능) 모델이 수행하는 것을 원칙으로 한다.
2. 하급(경량) 모델이 생성하거나 수정한 지침·결과물은 상급 모델의 심판을 통과해야 효력을 가진다.
3. 하급 모델은 심판을 수행할 수 없고, 심판이 필요하다는 표시([심판: 필요])만 남긴다.
4. 상급 모델을 즉시 쓸 수 없는 경우 결과물은 "심판 대기" 상태로 두고 최종본으로 사용하지 않는다.

## 제3조 관할

헌법재판소는 다음을 심판한다.

1. 위헌심판: 지침이 헌법(목적·정체성·우선순위·금지사항)에 위배되는지
2. 계층적합성심판: 지침의 내용이 올바른 계층(헌법~운영기록)에 배치되었는지
3. 충돌심판: 지침 간 내용이 충돌할 때 어느 지침을 우선할지
4. 승격심판: 반복된 유권해석·판례를 시행규칙 또는 법률로 승격할지
5. 폐지심판: 중복되거나 사문화된 지침을 폐지·통합할지
6. 이행확인심판: 판례·결정문의 재발방지 기준과 이행 조치가 대상 지침에 실제로 반영되었는지

# 제2장 심판 개시 (트리거)

## 제4조 자동 심판 (필수)

아래 경우 AI는 요청이 없어도 반드시 심판을 수행한다.

| 시점 | 심판 종류 |
|---|---|
| 새 지침을 생성한 직후 | 위헌심판 + 계층적합성심판 |
| 기존 지침을 수정한 직후 | 위헌심판 + 계층적합성심판 + 충돌심판 |
| 유권해석이 같은 쟁점으로 3회 이상 누적 | 승격심판 |
| 지침 체계 전체를 처음 생성 완료한 직후 | 전수 계층적합성심판 |
| 재발방지 기준·이행 조치가 포함된 판례·결정례 생성 직후 | 이행확인심판 |
| 이행 조치가 '대기' 상태인 채 다음 작업을 시작하려 할 때 | 이행확인심판 (먼저 수행) |

## 제5조 청구 심판 (사용자 요청)

사용자가 아래처럼 말하면 즉시 해당 심판을 개시한다.

```text
검수해줘 / 심사해줘 / 헌재 돌려줘 / 위헌인지 봐줘 /
계층 맞는지 봐줘 / 지침 구조 맞는지 검사해줘 / 전체 지침 검수해줘 /
이 지침 충돌 안 나? / 이거 승격시켜도 돼?
```

대상 문서를 지정하지 않으면 전수 심사로 처리하되, 시작 전에 범위를 한 번 확인한다.

# 제3장 심판 절차

## 제6조 심판 순서

```text
1. 심판 대상 문서를 실제로 읽는다. (읽지 않은 문서는 심판하지 않는다)
2. 헌법과 관련 상위 문서를 읽는다.
3. 위헌심판을 먼저 한다. (헌법 위반이면 계층이 맞아도 위헌)
4. 계층적합성심판을 한다. (제8조 판정표 적용)
5. 충돌심판을 한다. (관련 문서 간 모순 확인)
6. 결정문을 작성한다. (제10조 템플릿)
7. 주문에 따른 이행 조치(이관·수정·폐지)를 수행하거나 제안한다.
8. 결정례를 09_헌법재판소/결정례/에 저장하고 changelog에 기록한다.
```

## 제7조 위헌심판 기준

아래 하나라도 해당하면 위헌이다.

1. 헌법의 목적·정체성과 반대되는 내용을 담고 있다.
2. 헌법의 절대 금지사항을 허용하고 있다.
3. 헌법의 우선순위를 뒤집는 기준을 만들고 있다.
4. 헌법이 정한 품질 최저선보다 낮은 통과 기준을 만들고 있다.
5. 하위 지침이 상위 지침을 무시하라고 지시하고 있다.

## 제8조 계층적합성심판 기준 (오배치 판정표)

문서 안의 내용을 조각 단위로 검사하여, 아래 판정표에 어긋나면 오배치로 판정한다.

| 발견된 내용 | 올바른 계층 | 오배치 예시 (위법) |
|---|---|---|
| 목적, 정체성, 절대 금지, 최상위 우선순위 | 헌법 | 법률에 프로젝트 정체성 정의가 있음 |
| 분야 정의, 허용/금지, 품질 원칙 | 법률 | 헌법에 특정 분야 세부 금지 목록이 있음 |
| 작업 순서, 단계 이동·회귀 조건 | 시행령 | 법률에 1→2→3 단계 절차가 있음 |
| 점수표, 배점, 체크리스트, PASS/FAIL 수치 | 시행규칙 | 법률·시행령에 점수표가 있음 |
| 프롬프트 원문, 모델명, 파라미터, 파일명, 스타일 | 고시 | 헌법·법률에 프롬프트나 모델명이 있음 |
| 실제 사례와 교훈 | 판례 | 법률에 특정 사례 서술이 있음 |
| 사용자 질의·답변 기반 해석 | 유권해석 | AI가 임의 확정한 기준이 유권해석에 있음 |
| 로그, 결과, 변경 이력 | 운영기록 | 지침 본문에 작업 로그가 섞여 있음 |

추가 검사 항목:

1. 문서 등급 표기와 실제 내용이 일치하는가.
2. 파일명 규칙 `[계층]_[분야]_[문서명]_v[버전].md`을 지켰는가.
3. 올바른 폴더(01_헌법~09_헌법재판소)에 있는가.
4. 상위·하위 문서 참조가 실제 존재하는 파일명인가.
5. 자주 바뀔 내용이 상위 계층에, 바뀌면 안 되는 내용이 하위 계층에 있지 않은가.

## 제9조 심판 점수표

| 항목 | 기준 | 배점 |
|---|---|---:|
| 합헌성 | 제7조 위헌 사유가 없는가 | 30 |
| 계층적합성 | 제8조 오배치가 없는가 | 30 |
| 무충돌성 | 관련 지침과 모순이 없는가 | 20 |
| 형식적합성 | 파일명·폴더·문서 정보 표기가 규칙대로인가 | 10 |
| 참조무결성 | 상위·하위 문서 참조가 실제와 일치하는가 | 10 |

## 결정 등급

| 등급 | 조건 | 효력 |
|---|---|---|
| 합헌 | 90점 이상, 위헌 사유 없음 | 그대로 사용 |
| 헌법불합치 | 70~89점, 위헌 사유는 없으나 오배치·충돌 존재 | 지정 기한(즉시~다음 작업 전)까지 수정·이관 후 재심판 |
| 위헌 | 제7조 위헌 사유 존재 또는 69점 이하 | 즉시 효력 정지. 수정·이관·폐지 전까지 해당 지침을 근거로 작업 금지 |

# 제4장 결정문

## 제10조 결정문 템플릿

심판 결과는 반드시 아래 형식으로 작성하고 결정례로 저장한다.

```markdown
# 결정례_[연도]헌[가/나/다][번호]_[대상문서명]

## 0. 사건 정보
- 사건번호: [예: 2026헌가1]  (가: 위헌/계층 심판, 나: 충돌 심판, 다: 승격·폐지 심판)
- 심판 종류: 위헌심판 / 계층적합성심판 / 충돌심판 / 승격심판 / 폐지심판
- 심판 대상: [문서명과 조항]
- 심판 개시 사유: 자동(생성/수정) / 사용자 청구
- 결정일: YYYY-MM-DD
- 사건 상태: 종결 / 미종결 (이행 조치 전부 완료 시에만 종결)

## 1. 심판 대상 조항
[문제가 된 내용 인용]

## 2. 쟁점
[무엇이 문제인가]

## 3. 판단
- 위헌 여부: [사유별 판단]
- 계층 적합성: [오배치 여부와 근거 — 제8조 판정표 항목 인용]
- 충돌 여부: [관련 문서와의 모순 여부]
- 심판 점수: [항목별 점수와 총점]

## 4. 주문
이 지침(조항)은 [합헌 / 헌법불합치 / 위헌]이다.

## 5. 이행 조치
| 조치 | 대상 | 내용 | 상태 |
|---|---|---|---|
| 이관 | [내용 조각] | [현재 위치] → [올바른 계층·문서] | 완료/대기 |
| 수정 | [조항] | [수정 내용] | 완료/대기 |
| 폐지 | [문서/조항] | [폐지 사유] | 완료/대기 |

## 6. 재발 방지 기준
앞으로 같은 유형의 오배치·위헌을 막기 위한 기준 한 문장.

## 7. 이행 추적
| 반영할 지침 | 반영 내용 | 상태 | 확인일 |
|---|---|---|---|
| [문서명] | [재발방지 기준을 어느 조항으로] | 반영완료 / 대기 / 반영불요 | YYYY-MM-DD |
```

## 제11조 결정의 효력

1. 위헌 결정된 지침은 수정 완료까지 존재하지 않는 것으로 취급한다.
2. 헌법불합치 결정된 지침은 지정 기한 안에 수정하고 재심판을 받는다.
3. 이관 조치는 기존 법·지침 수정 트리거 절차(계층별 분해 반영)를 따른다.
4. 모든 결정과 이행 조치는 changelog에 기록한다.
5. 같은 유형의 사건은 기존 결정례를 선례로 우선 적용한다.

## 제11조의2 이행확인심판

1. 심판 대상: 재발방지 기준 또는 이행 조치(이관·수정·폐지)를 포함한 모든 판례와 결정례.
2. 심판 절차:

```text
1. 판례·결정문의 이행 조치 표와 재발방지 기준을 읽는다.
2. 반영 대상 문서를 실제로 열어 해당 내용이 들어갔는지 확인한다.
   (문서명만 보고 반영됐다고 가정하면 안 된다)
3. 반영됨 → 이행 추적 표의 상태를 '반영완료'로, 확인일을 기록한다.
4. 미반영 → 즉시 반영을 수행하거나, 수행할 수 없으면 '대기' 상태와 사유를 보고한다.
5. 반영으로 인한 참조 무결성(상위·하위 문서 참조, 파일명)을 확인한다.
6. 결과를 changelog에 기록한다.
```

3. 모든 이행 조치가 '반영완료' 또는 '반영불요'가 되기 전에는 사건을 종결로 처리하면 안 된다.
4. '대기' 상태의 이행 조치가 남아 있으면, 관련 분야의 다음 작업을 시작하기 전에 이행확인심판을 먼저 수행한다.
5. 지침 수정을 동반한 이행은 수정 직후 자동 심판(위헌·계층적합성·충돌)도 함께 받는다. 이번 수정 자체도 심판 대상이다.

## 제12조 승격·폐지 심판 기준

1. 승격: 같은 쟁점의 유권해석이 3회 이상 반복 적용되었으면 시행규칙 승격을, 여러 분야에 걸쳐 적용되면 법률 승격을 결정한다. 승격 시 원 유권해석에는 승격 사실과 이동 위치를 남긴다.
2. 폐지: 두 문서가 같은 내용을 규정하면 상위 계층 문서로 통합하고 하위 중복을 폐지한다. 6개월 이상 참조되지 않고 현행 절차와 맞지 않는 지침은 폐지를 제안한다.
3. 승격·폐지는 사용자 승인 후 확정한다.

# 제5장 전수 심사

## 제13조 전수 심사 절차

사용자가 "전체 지침 검수해줘"라고 하거나 체계 최초 생성 직후에는 아래 순서로 전수 심사한다.

```text
1. 폴더 구조와 파일 목록을 확보한다.
2. 헌법을 먼저 읽고 심판 기준으로 고정한다.
3. 계층 순서(법률 → 시행령 → 시행규칙 → 고시 → 판례 → 유권해석)대로 문서별 심판한다.
4. 문서별 결정 등급을 종합표로 만든다.
5. 위헌·헌법불합치 문서의 이행 조치를 일괄 수행하거나 제안한다.
6. 종합 결정문 1건 + 문서별 결정례를 저장하고 changelog에 기록한다.
```

전수 심사 종합표 형식:

```markdown
| 문서 | 심판 점수 | 결정 | 주요 사유 | 이행 조치 |
```

# 부칙

1. 이 법은 지침 체계 생성 시 `09_헌법재판소/` 폴더에 배치한다.

```text
09_헌법재판소/
├── 헌법재판소법_v1.0.md
└── 결정례/
    └── 결정례_[연도]헌[가/나/다][번호]_[대상문서명].md
```

2. 이 법 자체도 심판 대상이다. 단, 이 법의 개정은 사용자 승인을 받아야 한다.
