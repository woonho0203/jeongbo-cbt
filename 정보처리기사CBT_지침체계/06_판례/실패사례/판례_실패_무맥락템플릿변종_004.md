# 판례_실패_무맥락템플릿변종_004

## 사건명

전수 해설 검수(2026-07-19) 중, 판례_003(2026-07-12) 때 "전량 재작성 완료"로 종결 처리된 무맥락 템플릿 문제가 **재작성 자체에 쓰인 새 생성기**로 인해 다른 형태로 재발한 사례. exam_2021-1·2021-2·2021-3(+2023-3·2024-3 각 1건) **103문항**이 "긍정형 개념 식별 문제임." 등 5종 헤더와 "정답 조건에 해당함/해당하지 않음", "구체적 근거: 정답 보기는 문제에서 요구한 대상, 기능, 목적을 직접 설명하지만…", "주의(함정): 긍정형 문제에서는…" 같은 **문제 유형별 고정 커넥터 문장**을 문항 내용과 무관하게 그대로 복사해 쓰고 있었다.

## 결과

- 제2조(불충분 해설 후보): 길이·구체값 조건은 충족해 통과.
- 제2조의2(무맥락 템플릿 리터럴 탐지): 판례_001 당시 문구 7종만 찾으므로 **0건 — 재차 미탐**.
- 실제 확인(수동 대조): 103문항의 오답 분석·주의(함정) 문장이 문제 내용과 무관하게 동일 유형 내에서 글자 그대로 반복. 예) exam_2021-1 Q66("문자열을 정수형으로 변환하는 함수는?" — 코드 실행이 전혀 없는 순수 개념 문제)에 "코드·알고리즘 실행 결과형 문제임" 라벨과 "과정 1: 초기 변수, 배열, 포인터, 출력문 위치를 먼저 확인함." 같은 가짜 실행 추적 단계가 붙음.

## 실패 이유

1. 판례_003 재발방지 기준("금지 패턴은 반드시 탐지 명령과 짝짓는다")을 리터럴 문자열 갱신으로만 이행하고, **재작성에 투입되는 새 생성기의 산출물을 사전 검증하지 않았다.** 재작성 직후 재검수(2026-07-12)가 "템플릿 0건"으로 통과한 것은 옛 리터럴만 검사했기 때문이며, 새 생성기가 만든 신종 템플릿을 검사 대상에 넣지 못했다.
2. 리터럴 문자열 블랙리스트 자체가 구조적으로 회피에 취약하다 — 표현만 바꾸면 항상 통과한다. 판례_001(원조)→결정례_2026헌가4(1차 갱신)→**본 사건(2차 통과)**까지 같은 실패가 반복됐다.

## 적용 기준 (교훈 한 문장)

무맥락 템플릿 탐지는 리터럴 문자열 블랙리스트만으로 끝내지 않는다. 재작성에 새 생성기·새 프롬프트를 투입할 때는 산출물 표본을 사람이 먼저 읽고, 서로 다른 문항에서 문장이 그대로 반복되는지(구조적 신호)까지 확인한 뒤 배포한다.
