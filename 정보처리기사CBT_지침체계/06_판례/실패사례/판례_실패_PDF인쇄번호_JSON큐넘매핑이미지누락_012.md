# 판례_실패_PDF인쇄번호_JSON큐넘매핑이미지누락_012

## 사건명

2016년 1회 학습 모드 Q5에서 "다음 트리를 후위 순회(Post Traversal)할 경우 가장 마지막에 탐색 되는 것은?" 문항의 트리 이미지가 화면에 표시되지 않은 사례.

## 결과

원본 PDF를 직접 확인한 결과, 해당 문항에는 루트 A, 자식 B·C, 단말 D·E·F로 구성된 트리 그림이 존재했다. 앱 JSON에서는 이 문항이 `exam_2016-1.json` Q5였지만, PDF 1쪽 오른쪽 컬럼의 인쇄 번호는 `10.`으로 표시되어 있었다.

조치 결과:

| 대상 | 조치 | 결과 |
|---|---|---|
| `data/exam_2016-1.json` Q5 | `image: "images/2016-1_q5.png"` 추가 | 반영완료 |
| `public/images/2016-1_q5.png` | PDF 트리 영역만 재크롭 | 반영완료 |
| API 검증 | `/api/exam/start`에서 Q5 image 필드 확인 | 정상 |
| 정적 파일 검증 | `/images/2016-1_q5.png` 200 OK 확인 | 정상 |

## 실패 이유

1. 기존 이미지 추출 절차가 PDF 인쇄 번호 또는 `nearest_question_above()` 결과를 JSON `qnum`과 동일하다고 가정했다.
2. 2016년 초기 회차 PDF는 인쇄 번호와 기존 JSON의 앱 표시 `qnum`이 어긋나는 구간이 있어, 번호만 기준으로 삼으면 실제 자료가 다른 JSON 문항에 매핑되거나 누락될 수 있다.
3. 기존 자동점검 제4조는 `image` 필드가 이미 있는 문항의 PNG 존재 여부만 보았으므로, `stem`이 "다음 트리"처럼 자료를 전제로 하는데 `image` 필드 자체가 없는 경우를 잡지 못했다.

## 적용 기준

PDF 자료 삽입은 PDF 인쇄 번호만으로 확정하지 않는다. PDF `stem` 핵심 문구와 JSON `stem`을 교차 대조해 최종 JSON `qnum`을 확정하고, 자료 필요 문항인데 `image`·`table`이 모두 없는 후보를 자동점검으로 별도 적발한다.
