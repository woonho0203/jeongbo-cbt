# 판례_실패_해설교차문항재사용오염_009

## 사건명

사용자 청구("문제 중에 이미지가 잘렷거나 표 문제 검수" → "전수오염검사")에 따라 이미지·표 검수 도중 `exam_2018-3.json` Q45(고정 분할 외부 단편화 계산)의 해설에 "응집도는 모듈 내부 요소의 관련 정도이고 결합도는…"이라는 전혀 다른 주제(SW 설계 결합도)의 개념 정의가 그대로 박혀 있음을 발견했다. 이를 단서로 전체 3,568문항의 해설에서 **동일한 "개념 정의" 문장이 서로 다른 공식 과목(subject 1~5) 3개 이상에 걸쳐 재사용된 사례**를 전수 탐지한 결과, 41문항에서 실제로 무관한 문제에 다른 문항의 개념 정의가 잘못 삽입돼 있음을 확인했다.

## 결과

- 1차 표본(스캔): "개념 정의:" 줄과 오답 분석 각 줄을 추출해 완전히 동일한 문구가 몇 개 문항에 재사용됐는지 집계 → 재사용 빈도 3회 이상인 문구가 312개, 이 중 과목 3개 이상에 걸친 것이 30개.
- 30개 문구를 실제 문항(stem·options·answer)과 대조해 문구가 진짜 그 문항 주제와 무관한지 확인 → 41문항이 실제 오염(예: HDLC 프레임 종류 문제에 응집도/결합도 정의, ARP 문제에 캐시 정의, IPv4 클래스 문제에 UML 모델링 정의, "Dual Stack" 보기에 자료구조 스택(LIFO) 정의가 이름만 같아서 잘못 붙는 등).
- 41문항 전부 실제 문항 내용에 맞는 정의·오답 근거로 재작성. 재검사 결과 잔존 오염 0건(과목 3개 이상 걸친 문구는 응집도/결합도 등 실제 그 주제인 문항에서만 재사용되는 정상 사례 1건으로 수렴).

## 실패 이유

1. 헌법 제5조 2호("다른 문제·다른 회차의 해설·이미지·표를 섞지 않는다")가 이미 최상위로 금지하는 사항인데도, 과거 대량 해설 재작성(무맥락 템플릿 제거 라운드, 2026-07-12~19) 과정에서 "개념 정의" 한 줄을 생성기가 **문항이 아니라 재사용 가능한 문구 풀에서 근접 선택**해 채운 것으로 추정되며, 이때 실제로는 무관한 주제의 정의가 섞여 들어갔다.
2. 기존 자동 점검(고시_검수_자동점검명령 제2조·제2조의2·제2조의3)은 해설이 **내용 없는 일반 문구(무맥락 템플릿)**인지만 본다. 이번 사례는 반대로 **내용은 있지만 다른 문항 것**이라, "짧다/공허하다/커넥터가 반복된다" 어떤 기준으로도 걸리지 않았다. 완전히 새로운 실패 유형이다.
3. 오염 문구 상당수는 영문 약어(예: `PAM`, `ARP`, `Dual Stack`, `C Class`)가 보기로 쓰인 문항에 집중됐다 — 생성기가 보기 텍스트의 표면적 유사어(예: "Stack"이라는 단어)로 잘못된 정의를 끌어왔을 가능성을 시사한다.

## 탐지 방법 (재현 가능한 절차)

1. 각 문항의 해설에서 "- 개념 정의: ..." 줄과 "- N번 <보기>: <설명>" 형태의 오답 분석 줄을 정규식으로 추출한다.
2. 완전히 동일한 문구가 등장하는 모든 (파일, qnum, subject) 인스턴스를 모은다.
3. 같은 문구를 사용하는 인스턴스들의 `subject`(1~5, 5개뿐인 공식 과목 분류) 값이 **3개 이상으로 갈라지면** 교차 오염 후보로 표시한다 (같은 주제라면 보통 1~2개 과목 안에 머무른다).
4. 후보 문구별로 실제 stem·options를 읽어, 그 문구가 진짜 해당 문항 주제를 설명하는지 대조한다(예: "응집도/결합도" 정의가 실제로 응집도/결합도를 묻는 문항에서만 쓰이는지).

## 적용 기준 (교훈 한 문장)

무맥락 템플릿 탐지(공허한 문구)와 별개로, **완전히 동일한 "개념 정의" 문구가 서로 다른 과목 3개 이상에 걸쳐 재사용되는지**를 주기적으로 검사해야 한다 — 내용이 그럴듯해도 다른 문항 것이면 헌법 제5조 2호 위반이다.
