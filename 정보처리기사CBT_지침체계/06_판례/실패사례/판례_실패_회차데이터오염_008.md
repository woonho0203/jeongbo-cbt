# 판례_실패_회차데이터오염_008

## 사건명

사용자 청구("문제들 전부 제대로 올라갓는지 검수시작" → "전체 검수")에 따라 전체 34개 데이터 파일을 각자의 PDF 원본과 자동 교차 대조한 결과, `data/exam_2022-1.json`(2022년 1회, 100문항)이 실제로는 `data/exam_2022-2.json`(2022년 2회)의 내용을 거의 그대로 담고 있고 진짜 2022년 1회 문항이 아님을 발견한 사례.

## 결과

`exam_2022-1.json`의 stem을 실제 PDF(`2022년1회_기사필기 기출문제.pdf`) 전체 텍스트와 대조하자 **100문항 중 5문항만 일치**했다. 반대로 `exam_2022-2.json`과 대조하면 **98문항이 같은 순번에서 완전히 동일**했다(문항 본문·보기 문자열까지 일치). 즉 `exam_2022-1.json`은 2022-2의 내용이 examId만 "2022-1"로 붙은 채 저장된 것이었다.

이 검증은 34개 데이터 파일 전체를 대상으로 자동 스크립트를 돌려, 각 파일이 (1) 자기 자신의 PDF와 얼마나 일치하는지, (2) 다른 33개 PDF 중 어느 것과 가장 잘 맞는지를 함께 계산하는 방식으로 이뤄졌다. `exam_2022-1`을 제외한 나머지 33개 파일은 모두 자기 자신의 PDF와 86~100% 일치해 정상으로 확인됐다(2016년 회차의 낮아 보이는 수치는 보기가 이미지로 인쇄된 PDF 구조 때문이며 다른 회차와 겹치지 않았다).

## 실패 이유

1. 원인은 특정되지 않았으나(과거 세션의 수동 데이터 보정 중 실수로 추정), 최소 이번 세션 이전부터 `exam_2022-1.json`이 이미 `exam_2022-2.json`의 복사본이었던 것으로 보인다.
2. 지금까지의 모든 자동 점검(고시_검수_자동점검명령 제1~4조의2)은 **파일 내부의 구조적 정합성**(필수 필드, 보기 구별, 이미지 경로, 셔플 재매핑)만 검사했지, **파일이 자신의 examId에 맞는 PDF 원본과 실제로 대응하는지**는 한 번도 검사하지 않았다. 그래서 examId가 다른 회차의 내용을 그대로 담고 있어도 모든 구조적 점검을 통과했고, 100문항이 몇 달간(추정) 무검사로 배포됐다.

## 조치

PDF(`2022년1회_기사필기 기출문제.pdf`)에서 직접 100문항을 재추출했다(2열 레이아웃 대응 단어 좌표 분리 + 정답표 페이지 파싱). 다음을 확인·복원했다:
- 정답 100개 전부 PDF 정답표(`1.④ 2.② ...`)와 대조해 100/100 일치 확인.
- 보기가 다이어그램·표·박스형 결과인 3문항(Q44 E-R 표기 기호, Q57 SQL UNION ALL 결과 테이블, Q79 Python 반복문 출력)은 고배율 렌더링으로 시각 판독해 텍스트로 전사하거나(Q44는 동일 문항이 exam_2017-1 Q19에 이미 있어 표기 관례를 대조 확인) 표 이미지를 새로 삽입(Q57 → `images/2022-1_q57.png`).
- 페이지 헤더/푸터("정보처리기사 필기 기출문제", 쪽번호)가 보기 끝에 섞여 들어간 오염 14건을 정리했다.
- 100문항 전체에 무맥락 템플릿 문구 없이 실제 근거를 담은 해설을 새로 작성했다(고시_해설_해설형식 준수, 자체 채점 결과 제2조/제2조의2/제2조의3 히트 0건).

## 적용 기준 (교훈 한 문장)

구조적 자동 점검(필드·형식·렌더링)을 통과했다는 것이 "이 파일이 올바른 회차의 내용"이라는 뜻은 아니다 — **examId·회차 라벨과 실제 PDF 내용의 대응 관계는 별도로, 주기적으로 전수 대조**해야 한다.
