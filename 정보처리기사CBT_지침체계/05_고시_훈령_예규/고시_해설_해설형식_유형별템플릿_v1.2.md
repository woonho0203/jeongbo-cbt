## 제2조 공통 해설 형식

짧은 해설:

```text
정답 이유 1~2문장
오답1 · 오답2 · 오답3 → 각각 해당하지 않음
```

풀이가 필요한 경우:

```text
핵심 공식 또는 판단 기준을 먼저 쓴다.
문제의 값에 적용한 계산 과정을 쓴다.
따라서 정답은 N번이다.
오답1 · 오답2 · 오답3 → 각각 해당하지 않음
```

상세(정의·오답비교) 구조: ① 개념 정의 → ② 정답 분석 → ③ 오답 분석(보기별) → ④ 함정·주의점 → ⑤ 암기 팁.

## 제2조의2 보기 번호 표기 규칙 (셔플 안전)

> 앱은 매 세션 보기를 무작위로 섞고(`public/js/exam.js`), 해설 속 보기 번호를 `remapExplanationNumbers()`로 화면 순서에 맞게 바꾼다. 따라서 해설의 번호 표기는 이 재매핑이 정확히 동작하는 형태여야 한다. 아래 규칙을 어기면 화면에 중복·누락된 번호가 표시된다 (판례_006: 376문항 실측).

**1. 보기를 가리킬 때는 `N번` 단위로 각각 쓰는 것을 원칙으로 한다.**

재매핑은 `·`·`,`·`、`로 구분한 나열(`1·2·4번`)까지는 펼쳐서 처리하지만, 그 밖의 구분자(`및`·`와`·`과`·`~`·`/`)로 이은 나열은 처리하지 못한다. 구분자에 의존하지 않도록 각각 `N번`으로 쓰는 편이 안전하다.

```text
O  1번·2번·4번은 모두 올바른 설명이다.      ← 가장 안전
O  정답 3번은 ~이므로 틀리다.
△  1·2·4번은 모두 올바른 설명이다.         ← 앱이 처리하지만 구분자에 의존
X  1 및 2번은 모두 올바른 설명이다.        ← 앞의 1이 재매핑되지 않아 번호가 깨진다
X  1~2번은 모두 올바른 설명이다.
```

**2. 보기가 아닌 항목에는 `N번`·`①②③④`를 쓰지 않는다.** 문제 본문의 항목(㉠㉡㉢), 비트 위치, 트랙 번호, PASS 회차, 단계 번호 등은 보기 번호가 아니므로 재매핑 대상이 되면 값이 변조된다. 번호 대신 **내용이나 다른 표기**를 쓴다.

```text
O  비트 0, 비트 2, 비트 4를 1로 만들려면      (exam_2016-1 Q25 시정 예)
X  0번, 2번, 4번째 비트를 1로 만들려면        ← '2번'이 보기 번호로 오인돼 변조된다

O  인스트럭션 페치 → 디코딩 → 오퍼랜드 페치 순이다   (exam_2016-1 Q39 시정 예)
X  ③ 인스트럭션 페치 → ② 디코딩 → ④ 오퍼랜드 페치 순이다
```

**3. 서수는 `N번째`로 쓴다.** 재매핑은 `N번째`를 보기 번호에서 제외하므로 안전하다.

**4. 보기 내용을 인용할 때는 번호보다 내용을 우선한다.** 번호만 나열하는 것보다 정답·오답의 실제 표현을 함께 적는 편이 셔플과 무관하게 안전하고 교육적으로도 낫다.

## 제2조의3 수식(LaTeX) 표기 규칙

> 앱은 KaTeX를 정적으로 내장(`public/vendor/katex/`)하고, `#app` DOM 변화를 감지해(`public/js/util.js`의 `renderMathIn()` + `MutationObserver`) `$...$` 안의 LaTeX를 수식으로 렌더링한다. stem·options·explanation에 아래 기준으로 LaTeX를 적용한다.

**1. 기호만으로 된 순수 수식은 `$...$`로 감싼다.** 분수, 지수, 오버라인(보수), 그리스 문자, 로그 밑수처럼 일반 텍스트로는 정확히 표현되지 않거나(오버라인 결합문자 U+0305는 폰트에 따라 위치가 어긋나거나 안 보인다) 가독성이 떨어지는 수식이 대상이다.

```text
O  $F = \overline{A} + \overline{B}$
O  $T = \frac{1}{2W}$
O  $-2^{n-1} \sim 2^{n-1}-1$
O  $B \cdot \log_{2}(1+S/N)$
```

**2. 한글이 섞인 표현은 한글을 수식 밖에 둔다.** KaTeX 내장 폰트는 한글 글리프를 지원하지 않아 `$...$`(또는 `\text{}`) 안에 한글이 들어가면 렌더링되지 않거나 깨진다. 숫자·기호 부분만 감싼다.

```text
O  기존 데이터의 $\frac{1}{2}$
X  $기존 데이터의 \frac{1}{2}$
X  $\frac{수행시간 \times 10^6}{연산개수}$
```

**3. 특별한 렌더링 없이도 일반 폰트로 정확히 표시되는 기호는 그대로 둔다.** 관계대수 연산자(π·σ·▷◁), 유니코드 위·아래첨자(²·₂), 비트 연산자(`^`), CIDR `/24` 표기 등은 LaTeX로 바꾸지 않는다. LaTeX는 텍스트로 정확히 표현되지 않는 경우에만 쓴다.

**4. 이미 확정된 수식 값의 표기만 바꾼다.** LaTeX 적용은 기존에 PDF 대조·유권해석으로 확정된 수학적 값을 그대로 다른 문법으로 다시 쓰는 것이다(헌법 제5조 1호가 요구하는 "원문 대조"는 값을 새로 만들 때 적용되며, 값이 같은 표기 변경에는 적용되지 않는다). 값 자체를 바꾸려면 문제추출법 절차를 따른다.

**5. `N번` 보기 번호 재매핑(제2조의2)과 충돌하지 않는다.** 수식은 `$...$`로 닫히므로 안의 숫자는 `remapExplanationNumbers()`의 `N번` 정규식과 부딪히지 않는다. 다만 수식 바로 뒤에 `번`을 붙이지 않는다 — `번` 참조는 항상 수식 밖에 별도로 쓴다.

```text
O  정답은 2번 $F=A$다.
X  정답은 $F=A$번이다.
```

## 제3조 유형별 템플릿

**트리** — 차수=최대 자식 수, 단말=자식 없는 노드 수, 순회(전위 루트→좌→우 / 중위 좌→루트→우 / 후위 좌→우→루트).
```text
그림의 트리에서 자식이 가장 많은 노드는 자식 3개를 가지므로 트리의 차수는 3입니다.
2 · 4 · 5 → 각각 해당하지 않음
```

**그래프·제어흐름도** — DFS/BFS는 시작 정점·선택 순서·최종 방문 순서. McCabe V(G)=E−N+2 또는 폐쇄영역+1.
```text
McCabe 순환 복잡도는 V(G)=E-N+2로 계산합니다. 간선 수와 노드 수를 대입하면 4입니다.
3 · 5 · 6 → 각각 해당하지 않음
```

**프로그램 구조도** — Fan-In=호출하는 상위 모듈 수, Fan-Out=호출하는 하위 모듈 수.

**릴레이션** — 카디널리티=행 수, 차수=열 수.

**스케줄링** — 공식 + 각 작업 계산값 + 정렬 기준(높은값/낮은값 우선). 예: HRN=(대기+서비스)/서비스.

**세그먼트 테이블** — 기준 주소·길이 읽고, 변위<길이 확인, 물리주소=기준주소+변위.

**SQL** — UNION(중복 제거)/UNION ALL(중복 포함) 먼저 명시, FROM→WHERE→GROUP BY/HAVING→SELECT→ORDER BY 흐름.

**코드** — 코드 전체 재설명 금지, 값 바뀌는 줄만 추적, "최종 출력값은 ..." 필수.

**잘못된 문장** — 정답 보기가 왜 틀렸는지 한 문장으로 바로.

**키워드** — 결정 단서 ↔ 정답 용어 연결, 유사 보기 차이 한 줄.

**종류·순서** — 정답 순서 먼저 제시 + 각 단계 의미 짧게.

## 제4조 절대 금지 문장 (무맥락 템플릿)

- `문제에서 묻는 조건과 맞지 않으므로 틀림`
- `문제에서 묻는 범주에 속하므로 정답 조건에서 제외됨`
- `문제 단서와 다른 개념이므로 정답이 아님`
- `계산하거나 표와 대조했을 때 도출되는 값임`
- `최종 출력값 또는 계산 결과에 해당하므로 정답임`

## 제5조 붙여넣기용 작성 프롬프트

```text
정보처리기사 필기 CBT용 해설을 작성해줘.

조건:
1. 문제 원문, 보기, 정답 번호는 바꾸지 말고 explanation만 작성한다.
2. 해설은 초보 수험생이 바로 이해할 수 있게 2~5문장으로 쓴다.
3. 정답이 맞는 이유를 먼저 쓰고, 마지막 줄에 오답 보기를 "A · B · C → 각각 해당하지 않음" 형식으로 정리한다.
4. 그림·표 문제는 읽어야 하는 값(행/열 수, 자식 수, 방문 순서, 기준 주소, 계산값 등)을 반드시 적는다.
5. 코드 문제는 변수 변화와 최종 출력값 중심으로 설명한다.
6. SQL 문제는 FROM/WHERE/SELECT 또는 집합 연산 결과를 실제 결과 행과 연결한다.
7. 틀린 것을 고르는 문제는 정답 보기가 왜 틀렸는지 먼저 설명한다.
8. 모르는 내용을 꾸며내지 말고, 그림·표 정보가 부족하면 "그림/표 확인 필요"라고 표시한다.
9. JSON에 넣을 수 있게 줄바꿈은 최소화하고, Markdown 제목이나 장식은 쓰지 않는다.
```

## 제6조 데이터 입력 체크리스트
