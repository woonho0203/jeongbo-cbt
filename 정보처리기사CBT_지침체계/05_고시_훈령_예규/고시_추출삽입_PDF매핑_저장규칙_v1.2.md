## 제1조의2 PDF 인쇄번호 ↔ JSON qnum 보정 규칙

PDF의 인쇄 번호, 자동 추출기가 찾은 가까운 번호, JSON의 `qnum`은 항상 같다고 가정하지 않는다.

1. `scripts/extract_media.py`의 `nearest_question_above()` 결과는 확정값이 아니라 **후보 번호**다.
2. 자료 후보가 잡히면 PDF `stem`의 핵심 문구(공백 제거 10~30자)를 JSON `stem`과 대조해 최종 `qnum`을 확정한다.
3. PDF 인쇄 번호가 JSON `qnum`과 다르더라도 `stem` 핵심 문구가 일치하면 JSON `qnum` 기준으로 저장한다.
4. 저장 파일명과 JSON 경로는 반드시 보정 확정된 JSON `qnum`을 따른다.
5. 보정 사례는 보고서에 아래 형식으로 남긴다.

```text
exam_2016-1: PDF page 1 printed Q10 ↔ JSON Q5
stem key: 다음트리를후위순회
media: tree image → public/images/2016-1_q5.png
decision: PDF 인쇄번호가 아니라 JSON qnum 기준 저장
```

이미 확인된 대표 사례: `exam_2016-1.json` Q5는 앱·JSON 기준 Q5지만, 원본 PDF 1쪽 오른쪽 컬럼에서는 인쇄번호 `10.`으로 표시된 트리 후위 순회 문항이었다. 번호만 믿고 자동 추출하면 `images/2016-1_q5.png`가 생성되지 않으므로, 이 조의 `stem` 기반 보정 매핑을 적용해야 한다.

## 제2조 저장 규칙

- 이미지: `public/images/{examId}_q{qnum}.png` (경로 필드값은 `images/{examId}_q{qnum}.png`)
- 표: `<table>...</table>` HTML을 `table` 필드에.
- 삽입 대상 자료 유형: 그림·트리·그래프·제어흐름도·UML·구조도·네트워크도, 릴레이션·SQL 결과·스케줄링·세그먼트 테이블·진리표·상태표, 한 줄로 깨진 표.

## 제3조 자동 추출 스크립트

```text
scripts/extract_media.py  (2016~2023 처리)
scripts/extract_answers.py / extract_questions.py / extract_categories.py  (전체 재추출)
```

재추출 사전 요구: `pip install pdfplumber`

## 제4조 image / table 선택 기준 (요약)

```text
표가 깔끔하게 추출됨 → table
셀 병합·선·배치로 HTML이 깨짐 → image
그림·구조도 등 비표 자료 → image
```
