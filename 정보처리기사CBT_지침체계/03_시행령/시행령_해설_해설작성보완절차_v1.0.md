## 제1조 전체 절차 (신규 작성)

```text
1. 문항 유형 판별 (긍정형/부정형, 계산/코드/SQL/그림/표/키워드/순서)
2. 정답 보기·불변 필드 확인
3. 자료 문제면 image/table에서 핵심 값 읽기
4. 정답 이유 → (필요 시 풀이) → 오답 정리 순으로 작성 (05_고시 형식)
5. 자체 채점 (04_시행규칙 해설 채점표)
6. 85점 미만이면 4단계로 회귀, 이상이면 저장
```

## 제2조 전체 절차 (보완 — 검수 결과 기반)

```text
1. 검수 보고서(운영기록)의 보완·재검수·실패 목록 확보
2. 우선순위대로 정렬 (제4조)
3. 문항별 수정 (해설작성법·05_고시 형식 준수)
4. JSON 파싱 점검 + 앱 확인
5. 재검수 (검수법)
6. 실패 0개까지 반복
```

## 제3조 단계별 입력과 출력

| 단계 | 입력 | 출력 | 다음 단계 조건 |
|---|---|---|---|
| 유형 판별 | `stem` | 긍정/부정 + 세부 유형 | 유형 확정 |
| 핵심 값 읽기 | image/table | 계산값·순서·행열 등 | 자료 문제 한정 |
| 작성 | 정답·오답·핵심값 | `explanation` | 형식 충족 |
| 자체 채점 | explanation | 점수 | 85점 이상 |
| 저장 | 수정 JSON | 파싱 정상 | 앱 확인 통과 |

## 제4조 보완 우선순위 (회귀·처리 순서)

```text
1. 이미지·표 해설 연계 부족 문항
2. 명확한 비문·무맥락 템플릿 잔여
3. category_wrong-sentence 짧은 해설
4. category_sequence 짧은 해설
5. category_code 코드·SQL 흐름 보강
6. category_keyword 결정 단서 보강
7. category_calc 공식·대입값 보강
8. 원본 PDF 기준 누락 문항 복구 확인
```

## 제5조 회귀 기준

```text
자체 채점 85점 미만 → 작성(4단계)으로 회귀
JSON 파싱 오류 → 즉시 수정 후 재점검
재검수에서 실패 판정 → 해당 문항 재작성
치명 오류(정답-결론 불일치 등) → 즉시 수정, 회차 판정 보류
```

## 제6조 산출물 기록

- 작성·보완 결과 요약을 운영기록(시행 보고)에 남긴다.
- 반복 확인된 오류 유형(예: 무맥락 템플릿 재발)은 판례 후보로 기록한다.
- changelog에 변경 파일·문항 수·변경 이유 기록.
