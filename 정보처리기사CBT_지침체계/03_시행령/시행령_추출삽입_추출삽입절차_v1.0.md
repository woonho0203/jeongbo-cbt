## 제1조 전체 절차

```text
1. 백업 확인 (git status)
2. 자료 문제 후보 선별
3. PDF 번호 ↔ JSON qnum 보정 매핑 확인 (`stem` 핵심 문구 교차 대조)
4. 자동 추출 실행 (scripts)
5. image / table 판단 및 삽입
6. 자동 점검 (JSON·경로·HTML·자료 필요 누락 후보)
7. PDF 원본 대조 채점 (04_시행규칙)
8. 앱 화면 확인
9. 재작업 또는 종료 + 운영기록 기록
```

## 제2조 단계별 입력과 출력

| 단계 | 입력 | 출력 | 다음 단계 조건 |
|---|---|---|---|
| 1 백업 확인 | 현재 작업 트리 | 변경 전 상태 기록 | 변경 대상 파일·폴더 확인 완료 |
| 2 후보 선별 | PDF, JSON `stem` | 자료 문제 `qnum` 목록 | 후보 확정 |
| 3 보정 매핑 확인 | PDF 인쇄 번호, PDF `stem`, JSON `stem` | PDF 위치 ↔ JSON `qnum` 매핑표 | 번호와 `stem` 핵심 문구 일치 또는 불일치 사유 기록 |
| 4 자동 추출 | PDF, 추출 스크립트 | 크롭 후보 이미지/표 | 추출 산출물 생성 |
| 5 삽입 판단 | 추출 산출물 | `image` 또는 `table` 필드 | 표 깨짐 여부로 image/table 결정 |
| 6 자동 점검 | 수정된 JSON | 파싱·경로·HTML·자료 필요 누락 후보 점검 결과 | 오류 0건, 누락 후보 PDF 확인 완료 |
| 7 PDF 대조 채점 | JSON, PDF | 문제별 점수·판정 | 85점 이상 & 치명 오류 0 |
| 8 앱 확인 | 실행 앱 | 풀이/결과/오답/북마크 화면 확인 | 정상 렌더링 |
| 9 종료/재작업 | 채점 결과 | 회차 판정, 운영기록 | 회차 판정 = 통과/조건부통과 |

## 제2조의2 PDF 번호 ↔ JSON qnum 보정 매핑

1. 자동 추출기의 `nearest_question_above()` 또는 PDF 인쇄 번호는 **후보 번호**로만 사용한다.
2. 후보 번호가 JSON `qnum`과 다르거나, PDF 문항 순서가 앱 표시 순서와 다르게 보이면 PDF `stem` 핵심 문구(공백 제거 10~30자)로 JSON 문항을 다시 찾는다.
3. PDF 인쇄 번호와 JSON `qnum`이 달라도 `stem`이 일치하면 JSON `qnum` 기준으로 `image`/`table` 파일명을 저장한다.
4. 보정 매핑을 적용한 문항은 운영기록에 `PDF 페이지·PDF 인쇄번호·JSON qnum·근거 stem`을 남긴다.

## 제3조 image / table 결정 규칙

```text
표 추출 결과가 깔끔함 → table (HTML)
표에 셀 병합·선·배치가 있어 HTML로 깨짐 → image
그림·트리·그래프·구조도 등 비표 자료 → image
표처럼 보이지만 병합/선 때문에 깨짐 → image
```

## 제4조 회귀 기준

```text
자동 점검 오류(파싱·경로·HTML) → 5단계(삽입 판단)로 회귀
문제별 85점 미만 또는 치명 오류 → 3~5단계(보정 매핑·재추출·재삽입)로 회귀
앱 미표시 → 5단계로 회귀
회차 평균 90점 미만 또는 실패 1개 이상 → 회차 재작업
자료 필요 누락 후보가 실제 누락으로 확인됨 → 3~5단계(보정 매핑·재추출·재삽입)로 회귀
```
