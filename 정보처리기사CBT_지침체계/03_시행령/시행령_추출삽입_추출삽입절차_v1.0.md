## 제1조 전체 절차

```text
1. 백업 확인 (git status)
2. 자료 문제 후보 선별
3. 자동 추출 실행 (scripts)
4. image / table 판단 및 삽입
5. 자동 점검 (JSON·경로·HTML)
6. PDF 원본 대조 채점 (04_시행규칙)
7. 앱 화면 확인
8. 재작업 또는 종료 + 운영기록 기록
```

## 제2조 단계별 입력과 출력

| 단계 | 입력 | 출력 | 다음 단계 조건 |
|---|---|---|---|
| 1 백업 확인 | 현재 작업 트리 | 변경 전 상태 기록 | 변경 대상 파일·폴더 확인 완료 |
| 2 후보 선별 | PDF, JSON `stem` | 자료 문제 `qnum` 목록 | 후보 확정 |
| 3 자동 추출 | PDF, 추출 스크립트 | 크롭 후보 이미지/표 | 추출 산출물 생성 |
| 4 삽입 판단 | 추출 산출물 | `image` 또는 `table` 필드 | 표 깨짐 여부로 image/table 결정 |
| 5 자동 점검 | 수정된 JSON | 파싱·경로·HTML 점검 결과 | 오류 0건 |
| 6 PDF 대조 채점 | JSON, PDF | 문제별 점수·판정 | 85점 이상 & 치명 오류 0 |
| 7 앱 확인 | 실행 앱 | 풀이/결과/오답/북마크 화면 확인 | 정상 렌더링 |
| 8 종료/재작업 | 채점 결과 | 회차 판정, 운영기록 | 회차 판정 = 통과/조건부통과 |

## 제3조 image / table 결정 규칙

```text
표 추출 결과가 깔끔함 → table (HTML)
표에 셀 병합·선·배치가 있어 HTML로 깨짐 → image
그림·트리·그래프·구조도 등 비표 자료 → image
표처럼 보이지만 병합/선 때문에 깨짐 → image
```

## 제4조 회귀 기준

```text
자동 점검 오류(파싱·경로·HTML) → 4단계(삽입)로 회귀
문제별 85점 미만 또는 치명 오류 → 3~4단계(재추출·재삽입)로 회귀
앱 미표시 → 4단계로 회귀
회차 평균 90점 미만 또는 실패 1개 이상 → 회차 재작업
```

## 제5조 산출물 기록

- 삽입 결과: `media_insert_report_*.txt` (운영기록)
- 채점 결과: 이미지·표 점수 보고서 (운영기록, 양식은 04_시행규칙·05_고시)
- 이관: 삽입 완료 후 changelog에 변경 파일·문항 수 기록
