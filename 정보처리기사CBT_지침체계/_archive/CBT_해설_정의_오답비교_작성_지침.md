# 정보처리기사 CBT 해설 정의·오답비교 작성 지침 (개조식)

- 기준 시각: 2026년 05월 23일 11시 12분 26초

이 문서는 해설이 단순히 “무엇이 틀렸다”에서 끝나지 않고, 수험생이 개념을 이해하고 유사 문제를 다시 풀 수 있게 만드는 작성 기준임.

## 목표

해설은 아래 질문에 명확히 답해야 함.

- 정답 보기가 말하는 개념의 구체적인 정의
- 해당 개념이 맞거나 틀린 실제 기술적/논리적 이유
- 문제 요구(긍정형/부정형)에 따른 정답 도출 근거
- 나머지 보기가 정답이 아닌 구체적인 이유와 각 보기의 고유 개념 설명
- 유사 문제에서의 함정 탐색 방법
- 코드 및 계산 문제의 경우, 도출 과정과 논리적 오류 주의점

## 기본 작성 구조

모든 해설은 가독성을 높이기 위해 개조식(`~임`, `~함`, 명사형 종결)으로 작성해야 함.

권장 형식:

1. 개념 정의: 정답 보기의 핵심 개념을 먼저 정의함.
2. 정답 분석: 문제 조건과 비교해 왜 맞는지 또는 왜 틀린지 구체적으로 설명함.
3. 오답 분석: 나머지 보기는 각각 어떤 개념이며 왜 정답 조건에서 벗어나는지 개별적으로 정리함.
4. 함정 및 주의점: 비슷한 문제에서 주의할 단어나 판단 기준을 덧붙임.
5. 핵심 암기 팁이나 함정 주의 문구를 제공함.

## 절대 금지 패턴

도메인 지식 없이 어떤 문제에나 끼워 맞출 수 있는 무맥락 템플릿형 문장을 금지함.

금지 문장:

- `문제에서 묻는 조건과 맞지 않으므로 틀림`
- `문제에서 묻는 범주에 속하므로 정답 조건에서 제외됨`
- `문제 단서와 다른 개념이므로 정답이 아님`
- `계산하거나 표와 대조했을 때 도출되는 값임`
- `최종 출력값 또는 계산 결과에 해당하므로 정답임`
- 오답 보기들을 `나머지는 맞다`, `같은 범주다`로 묶어 처리하는 문장

실패 이유:

- 정답 보기의 실제 개념과 틀린 지점이 드러나지 않음.
- 오답 보기의 고유 개념을 설명하지 않음.
- 계산·코드 문제에서 중간 과정 없이 결과만 제시함.

## 부정형 문제 작성 규칙

대상 문장:

- `거리가 먼 것은?`
- `틀린 것은?`
- `옳지 않은 것은?`
- `해당하지 않는 것은?`
- `가장 적절하지 않은 것은?`

필수 기준:

- 해설의 시작은 정답 보기가 왜 “틀린 설명”인지 명시할 것.
- 정답 보기 안의 핵심 용어를 구체적으로 정의할 것.
- 나머지 보기는 맞는 설명인지, 아니면 문제 요구와 왜 다른지 개별 비교할 것.
- “정답은 N번이다”와 같은 단순 결론 기재 금지.

## 보기별 해설 필수 요소

정답 보기에는 반드시 아래 3가지를 포함함.

- 핵심 용어 정의
- 보기 문장의 틀린 부분 또는 맞는 부분
- 문제 요구와 연결한 결론

오답 보기에는 아래 2가지를 포함함.

- 보기의 핵심 개념
- 왜 정답 조건에 해당하지 않는지

## 긍정형 문제 작성 규칙

대상 문장:

- `옳은 것은?`
- `가장 적절한 것은?`
- `해당하는 것은?`
- `설명으로 맞는 것은?`

필수 기준:

- 정답 보기의 개념을 먼저 정의할 것.
- 문제 단서와 정답 보기가 어떻게 연결되는지 설명할 것.
- 나머지 보기는 어떤 개념과 혼동한 것인지 짧게 비교할 것.

## 계산·코드·SQL 문제 작성 규칙

대상 문제:

- C, Java, Python 코드 실행 결과 추적
- SQL 쿼리문 작성 및 결과 조회
- 서브넷 마스크, 프로세스 스케줄링 등 계산식 적용

필수 기준:

- 문제에 쓰인 핵심 문법이나 공식(예: 포인터, 상속, JOIN, SJF 알고리즘 등)을 먼저 정의할 것.
- 도출 과정을 단계별로 나누어 설명하거나, 반복문의 경우 변수 변화량을 명시할 것.
- 오답 보기가 유도하는 흔한 실수를 지적할 것.
- 중간 과정 생략 후 최종 결과값만 기재하는 것을 엄격히 금지함.

## 유사 문제 탐색 지침

해설 보강 전후에 비슷한 문제를 찾아 용어와 정답 논리가 서로 충돌하지 않는지 확인할 것.

검색 기준:

- `stem`
- `options`
- `explanation`

유사 문제 검수 기준:

- 같은 용어가 다른 문제에서 반대 의미로 설명되지 않았는가
- 부정형 문제와 긍정형 문제의 결론이 뒤섞이지 않았는가
- 같은 보기 문장이 다른 회차에서 다른 정답으로 처리되지 않았는가
- 해설이 특정 회차의 정답 번호에만 의존하지 않고 개념 기준으로 설명되는가

## 품질 판정

- [통과] 정의, 정답 이유, 오답 비교가 모두 구체적인 도메인 지식으로 작성됨. 코드·계산 문제는 도출 과정 포함.
- [보완] 정답 이유는 있으나 오답 비교나 용어 정의가 부족함.
- [재작성] “틀린 설명이다”, “해당하지 않는다”만 있고 이유가 없거나 과정 없이 결과만 도출함.
- [실패] 동어반복형 템플릿 또는 껍데기 문장으로 작성됨.

## 최종 체크리스트

- [ ] 문제 유형이 긍정형인지 부정형인지 먼저 확인했음.
- [ ] 정답 보기의 핵심 용어를 구체적으로 정의했음.
- [ ] 왜 맞는지 또는 왜 틀린지 실제 내용과 기술적 이유를 들어 설명했음.
- [ ] 나머지 보기가 왜 정답이 아닌지 개별 개념을 들어 비교했음.
- [ ] 유사 문제에서 같은 개념이 다르게 설명되지 않는지 검색했음.
- [ ] 해설만 읽어도 같은 유형의 함정을 다시 찾을 수 있음.
- [ ] 코드/SQL/계산 문제일 경우 변수 변화 추적이나 논리 전개 과정을 누락 없이 기재했음.
