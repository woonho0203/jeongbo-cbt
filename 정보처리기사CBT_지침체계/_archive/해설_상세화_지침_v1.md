## 2. 유형별 작성 규칙

### 2-1. 틀린설명형 (`X가 틀린 설명이다.`)

**문제 패턴**: "옳지 않은 것은?", "아닌 것은?", "틀린 것은?"

#### 패턴 A — `아닌 것` (범주 부재형)
> 문제: "~의 종류가 아닌 것은?" / "~에 해당하지 않는 것은?"

**작성법**: 정답이 왜 그 범주에 없는지 + 그 범주에 속하는 나머지를 열거

```
[현재] 데이터 버스가 틀린 설명이다.
[수정] 데이터 버스는 CPU와 메모리 간 데이터 전송 경로로, 입출력 제어장치가 아니다.
       입출력 제어장치에는 DMA, 채널, 입출력 프로세서 등이 있다.
```

```
[현재] 메모리(Memory)가 틀린 설명이다.
[수정] 마이크로 사이클은 명령어 처리 단계인 인출(Fetch)·간접(Indirect)·실행(Execute)로 구성된다.
       메모리(Memory)는 처리 단계가 아닌 저장 장치이므로 해당하지 않는다.
```

#### 패턴 B — `틀린 설명` (내용 오류형)
> 문제: "옳지 않은 설명은?" / "틀린 것은?"

**작성법**: 틀린 부분을 지적 + 올바른 내용으로 정정

```
[현재] 데이터베이스 공유도 최소화가 틀린 설명이다.
[수정] 병행제어의 목적은 공유도 최대화이다. '최소화'는 반대 개념이므로 틀린 설명이다.
       병행제어 목적: 응답시간 최소화, 시스템 활용도 최대화, 일관성 유지, 공유도 최대화.
```

```
[현재] 주기억장치에 상주가 틀린 설명이다.
[수정] 쉘(Shell)은 주기억장치에 상주하지 않고 필요할 때 디스크에서 로드된다.
       쉘 기능: 내장 명령어 제공, 파이프라인, 입출력 방향지정, 환경변수 관리.
```

### 2-2. 단순답변형 (`X이다.`)

**문제 패턴**: 트리 차수 계산, 인터럽트 구성, 통신 변조 방식 등

**작성법**: 정답 값이 나오는 이유 또는 개념 정의를 추가

```
[현재] 다음 그림에서 트리의 차수(degree)이 2이다.
[수정] 트리의 차수(degree)는 노드 중 자식 수가 가장 많은 노드의 자식 수이다.
       그림에서 최대 자식 수가 2이므로 트리의 차수는 2이다.
```

```
[현재] 인터럽트 벡터에 필수적인이 분기 번지이다.
[수정] 인터럽트 벡터(Interrupt Vector)는 인터럽트 발생 시 처리 루틴으로 점프하기 위한
       분기 번지(처리 루틴 주소)를 저장하는 테이블이다.
```

```
[현재] QPSK 변조 시 각 신호 간의 위상차이 90°이다.
[수정] QPSK(Quadrature Phase Shift Keying)는 4가지 위상(0°, 90°, 180°, 270°)을 사용하여
       한 번에 2비트를 전송한다. 따라서 각 신호 간 위상차는 90°이다.
```

## 4. 도메인별 기준 지식 (자주 출제되는 개념)

### 운영체제 / 하드웨어
- **마이크로 사이클**: 인출(Fetch) → 간접(Indirect) → 실행(Execute) → 인터럽트(Interrupt)
- **입출력 제어장치**: DMA, 채널(Channel), 입출력 프로세서 — 데이터 버스는 해당 없음
- **쉘(Shell)**: 사용자↔커널 인터페이스. 디스크 상주 (메모리 상주 아님)
- **병행제어 목적**: 공유도 최대화, 일관성 유지, 응답시간 최소화
- **인터럽트 벡터**: 처리 루틴 분기 번지(주소) 저장 테이블
- **emulation**: H/W를 S/W로 모방. I/O와 무관

### 데이터통신
- **QPSK**: 4위상, 90° 간격, 2비트/심볼
- **DES**: 대칭키 암호화 (비대칭 아님). 64비트 블록, 56비트 키
- **Reed-Solomon code**: 연집 오류 정정 부호 (블록 부호)

### 소프트웨어공학
- **결합도 강도(약→강)**: 데이터 < 스탬프 < 제어 < 외부 < 공통 < 내용
- **응집도 강도(약→강)**: 우연적 < 논리적 < 시간적 < 절차적 < 통신적 < 순차적 < 기능적
- **워크스루**: 오류 발견에 집중, 해결은 별도 (인스펙션은 공식 절차)
- **스파이럴 모델**: 계획→위험분석→개발→평가 사이클 반복 (한 번만 아님)

### 데이터베이스
- **시스템 카탈로그**: 읽기 가능, **수정 불가** (DBMS만 변경)
- **DML**: SELECT, INSERT, UPDATE, DELETE — GRANT는 DCL
- **파티셔닝**: 쿼리 성능 향상 + 백업/복구 속도도 향상 (느려지지 않음)
- **COCOMO 중간형**: 개발 공정별 세분화된 비용 산정 (옳은 설명임)

### 트리 / 자료구조
- **트리 차수(degree)**: 자식 수가 최대인 노드의 자식 수
- **터미널 노드(Leaf)**: 자식이 없는 노드 수
- **논리회로**: 카르노맵, 드모르간 법칙으로 간소화

## 5. 길이 기준

| 유형 | 목표 길이 |
|------|-----------|
| 틀린설명형 (아닌 것) | 2문장: 왜 아닌지 + 올바른 범주 예시 |
| 틀린설명형 (내용 오류) | 2문장: 틀린 부분 정정 + 올바른 내용 |
| 단순답변형 | 2문장: 개념 정의 + 정답 도출 근거 |
| 계산·그림형 | 1~2문장: 풀이 과정 + 결과 |
