# 정보처리기사 기출문제 해설 붙여넣기 지침

아래 지침은 2024년·2025년 회차별 기출과 유형별 문제에 해설을 붙일 때 그대로 사용할 수 있는 작성 기준이다.

## 기본 원칙

1. 문제 원문, 보기, 정답 번호는 임의로 바꾸지 않는다.
2. 해설은 수험생이 바로 이해할 수 있게 짧고 구체적으로 쓴다.
3. 정답이 왜 맞는지 먼저 설명하고, 오답은 마지막에 한 줄로 정리한다.
4. 그림·표·코드·SQL 문제는 눈으로 확인해야 하는 값을 해설에 반드시 적는다.
5. “그렇다”, “해당한다”처럼 막연한 표현보다 계산값, 방문 순서, 행/열 수, 출력값을 직접 적는다.
6. 틀린 것을 고르는 문제는 “정답 보기가 틀린 이유”를 먼저 쓴다.
7. 기출 앱 JSON에 넣을 때는 `explanation` 값만 교체하고 `stem`, `options`, `answer`, `image`는 유지한다.

## 공통 해설 형식

짧은 해설은 다음 형식을 기본으로 한다.

```text
정답 이유 1~2문장
오답1 · 오답2 · 오답3 → 각각 해당하지 않음
```

계산·코드·표 문제처럼 풀이 과정이 필요한 경우에는 다음처럼 쓴다.

```text
핵심 공식 또는 판단 기준을 먼저 쓴다.
문제의 값에 적용한 계산 과정을 쓴다.
따라서 정답은 N번이다.
오답1 · 오답2 · 오답3 → 각각 해당하지 않음
```

## 그림 문제 지침

`image` 필드가 있는 문제는 그림을 보지 않으면 풀 수 있는 정보가 빠져 있으므로, 해설에 그림에서 읽은 값을 반드시 넣는다.

### 트리

- 차수: 각 노드의 자식 수를 세고, 가장 큰 자식 수를 트리의 차수로 쓴다.
- 단말 노드: 자식이 없는 노드 수를 센다.
- 순회:
  - 전위/Preorder: 루트 → 왼쪽 → 오른쪽
  - 중위/Inorder: 왼쪽 → 루트 → 오른쪽
  - 후위/Postorder: 왼쪽 → 오른쪽 → 루트

예시:

```text
그림의 트리에서 자식이 가장 많은 노드는 자식 3개를 가지므로 트리의 차수는 3입니다.
2 · 4 · 5 → 각각 해당하지 않음
```

```text
INORDER 운행은 왼쪽 서브트리 → 루트 → 오른쪽 서브트리 순서입니다. 그림을 이 순서로 방문하면 D B A E C F가 됩니다.
A B D C E F · D B E C F A · A B C D E F → 각각 해당하지 않음
```

### 그래프·제어 흐름도

- DFS/BFS는 시작 정점, 인접 정점 선택 순서, 최종 방문 순서를 적는다.
- McCabe 순환 복잡도는 `V(G) = E - N + 2` 또는 `폐쇄 영역 수 + 1` 중 그림에서 확인하기 쉬운 방식으로 계산한다.

예시:

```text
McCabe 순환 복잡도는 V(G)=E-N+2로 계산합니다. 그림의 간선 수와 노드 수를 대입하면 순환 복잡도는 4입니다.
3 · 5 · 6 → 각각 해당하지 않음
```

### 프로그램 구조도

- Fan-In은 해당 모듈을 호출하는 상위 모듈 수다.
- Fan-Out은 해당 모듈이 호출하는 하위 모듈 수다.

예시:

```text
그림에서 모듈 F를 호출하는 모듈은 3개이므로 Fan-In은 3이고, F가 호출하는 모듈은 2개이므로 Fan-Out은 2입니다.
Fan-In : 2, Fan-Out : 3 · Fan-In : 1, Fan-Out : 2 · Fan-In : 2, Fan-Out : 1 → 각각 해당하지 않음
```

## 표 문제 지침

표가 이미지이거나 원문에 한 줄로 풀려 들어간 경우, 표의 의미를 해설에서 다시 구조화한다.

### 릴레이션 표

- 카디널리티 = 행/튜플 개수
- 차수 = 열/속성 개수

예시:

```text
해당 릴레이션에는 데이터 행이 4개 있고, 속성은 아이디·성명·나이·등급·적립금·가입년도로 6개입니다. 따라서 카디널리티는 4, 차수는 6입니다.
카디널리티 : 4, 차수 : 4 · 카디널리티 : 6, 차수 : 4 · 카디널리티 : 6, 차수 : 6 → 각각 해당하지 않음
```

### 스케줄링 표

- 사용 공식과 각 작업의 계산값을 모두 적는다.
- 정렬 기준이 “높은 값 우선”인지 “낮은 값 우선”인지 명확히 쓴다.

예시:

```text
HRN 우선순위 = (대기시간 + 서비스시간) / 서비스시간입니다. A=1.25, B=3.0, C=1.33, D=11이므로 높은 순서대로 D → B → C → A입니다.
A → B → C → D · A → C → B → D · D → A → B → C → 각각 해당하지 않음
```

### 세그먼트 테이블

- 먼저 세그먼트 번호의 기준 주소와 길이를 읽는다.
- 변위가 길이보다 작은지 확인한다.
- 물리 주소 = 기준 주소 + 변위

예시:

```text
세그먼트 2의 기준 주소는 222이고 길이는 198입니다. 변위 176은 198보다 작아 범위 안에 있으므로 물리 주소는 222 + 176 = 398입니다.
400 · 1928 · 1930 → 각각 해당하지 않음
```

### SQL 결과 표

- `UNION`은 중복 제거, `UNION ALL`은 중복 포함이라고 먼저 쓴다.
- SELECT 결과가 어떤 행 순서로 합쳐지는지 보기와 비교한다.

예시:

```text
UNION ALL은 두 SELECT 결과를 중복 제거 없이 그대로 합칩니다. R의 A 값 뒤에 S의 A 값이 이어지므로 결과는 1, 3, 1, 2입니다.
A 1 · A 3 2 · A 1 3 → 각각 해당하지 않음
```

## 유형별 해설 지침

### 필수 계산

공식 → 값 대입 → 결과 순서로 쓴다.

```text
카디널리티는 행 개수, 차수는 열 개수입니다. 표에서 행은 4개, 열은 6개이므로 정답은 카디널리티 4, 차수 6입니다.
```

### 필수 코드

코드 전체를 다시 설명하지 말고 값이 바뀌는 줄만 따라간다.

```text
초기값을 확인한 뒤 증감 연산이 적용되는 순서만 따라가면 최종 출력값은 4입니다.
다른 보기는 반복문 종료 시점의 변수 값을 잘못 계산한 경우입니다.
```

### 잘못된 문장 찾기

정답 보기가 왜 틀렸는지 한 문장으로 바로 말한다.

```text
워크스루와 인스펙션은 같은 의미가 아닙니다. 워크스루는 작성자 중심의 비공식 검토이고, 인스펙션은 체크리스트를 사용하는 공식 검토입니다.
```

### 키워드 찾기

문제의 결정 단서와 정답 용어를 연결한다.

```text
“서브타입은 기반 타입으로 교체 가능해야 한다”는 단서는 LSP, 즉 리스코프 치환 원칙을 가리킵니다.
ISP · DIP · SRP → 각각 해당하지 않음
```

### 종류·순서

순서 암기 문제는 정답 순서를 먼저 제시하고, 각 단계의 의미를 짧게 붙인다.

```text
결합도는 약한 순서부터 자료 결합 → 스탬프 결합 → 제어 결합 → 외부 결합 → 공통 결합 → 내용 결합입니다. 보기 중 이 순서와 일치하는 것을 고릅니다.
```

## 붙여넣기용 프롬프트

아래 문단을 해설 작성 요청에 그대로 붙여넣어 사용한다.

```text
정보처리기사 필기 CBT용 해설을 작성해줘.

조건:
1. 문제 원문, 보기, 정답 번호는 바꾸지 말고 explanation만 작성한다.
2. 해설은 초보 수험생이 바로 이해할 수 있게 2~5문장으로 쓴다.
3. 정답이 맞는 이유를 먼저 쓰고, 마지막 줄에 오답 보기를 “A · B · C → 각각 해당하지 않음” 형식으로 정리한다.
4. 그림 또는 표 문제는 그림/표에서 읽어야 하는 값(행 수, 열 수, 자식 수, 방문 순서, 기준 주소, 계산값 등)을 해설에 반드시 적는다.
5. 코드 문제는 변수 변화와 최종 출력값 중심으로 설명한다.
6. SQL 문제는 FROM/WHERE/SELECT 또는 집합 연산 결과를 실제 결과 행과 연결해서 설명한다.
7. 틀린 것을 고르는 문제는 정답 보기가 왜 틀렸는지 먼저 설명한다.
8. 모르는 내용을 꾸며내지 말고, 그림·표 정보가 부족하면 “그림/표 확인 필요”라고 표시한다.
9. JSON에 넣을 수 있게 줄바꿈은 최소화하고, Markdown 제목이나 불필요한 장식은 쓰지 않는다.
```

## 데이터 입력 체크리스트

- `image` 경로가 있는 문제는 경로를 삭제하지 않았는가?
- 표가 한 줄 텍스트로 깨진 경우 해설에서 행/열 또는 값 구조를 다시 설명했는가?
- 계산 문제에 공식과 대입값이 모두 들어갔는가?
- 순회·탐색 문제에 최종 방문 순서가 들어갔는가?
- 코드 문제에 최종 출력값이 들어갔는가?
- 부정형 문제의 해설이 “틀린 이유”로 시작하는가?
- 오답 정리 줄이 정답 보기를 제외한 보기만 담고 있는가?
